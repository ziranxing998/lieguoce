## 0. 摘要（一段话）

《列国策》的核心技术命题是：**用受限成本、节奏化的 LLM 决策，驱动一个 MMO 级别的"活君主"世界，且决策结果可被玩家全程复盘**。本基线给出的答案是：游戏服务端与 AI 决策服务**物理分离**，以**事件驱动 + 旬度快照批处理**为通信模式，以**规则引擎产生任务池、LLM 只做叙事与权衡**为成本分水岭，以**结构化表为权威 + 摘要向量为辅**的混合记忆方案守住"韩君最记仇"这类硬记忆。GDD 4.4 五条成本策略**全部可实现**，但其中三条（#1 覆盖率、#4 批处理、#5 熔断）需要补充架构级细节，并有需策划侧跟进的规格空缺（见 §5：v0.1 时 6 项，ARCH-002 修订后累计 10 项）。文武官职体系（GDD v0.2）**不改变架构骨架**，影响集中于事件 schema 归因链字段、官职数据模型与结算校验三点，见 §2.6。玩家自接 AI"客卿代驾"（ARCH-003 新增拍板）采用**玩家拉取-提交模式**（服务端不碰玩家 LLM），核心原则：**结构化动作白名单 + 信息平等 + agent_source 审计预埋**，见 §2.7 与 ADR-005。设计哲学经 ARCH-004 修订为"**框架内自由**"：权限红线（知识边界/白名单/审计/归因标记）刚性不变，限频从"防依赖"转向"**防作弊 + 防过载**"的宽松量级，拦截只针对五类作弊（见 §2.7.2）。玩家主权原则（ARCH-005 新增铁律）为"框架内自由"的宪法条款：**AI 权限 ⊂ 玩家手动权限**——手动覆盖/撤销、在线抢断、仅限手动动作三语义见 §2.8。终局身份（ARCH-010 新增）采用**托管 Auth 双通道 + 渐进式认领**（手机 OTP + WorkBuddy OAuth；游客行经 owner_id 认领升级为正式账号），见 ADR-006；客卿 BYO 直连最简版已在试玩版先行验证（密钥仅存浏览器 localStorage，白名单三类动作，产出以玩家名义进 player_actions 审计）。

## 1. GDD 4.4 成本策略可实现性评审

> 判定口径：**可行** = 架构上直接成立；**需调整** = 成立但 GDD 规格需补充；**有风险** = 存在可能颠覆体验或成本的隐患。

### 策略 1：自由对话仅服务 ≤5% 高层级玩家 —— **需调整**

- 可行性：成立。按一服 1 万 DAU 估算，5% = 500 名 L3 玩家 × 每日 3 次 ≈ **1500 次/日/服**的同步 LLM 调用，配流式输出与中等模型，成本可控（粗估 < $50/日/服 量级，见 §3.4 成本模型）。
- 限频实现是标准的**服务端令牌桶**（按玩家 ID，不受客户端信任），无技术难度。
- **架构坑**：GDD 4.4 只给 L3 朝堂对话定了"每日 3 次"，但**摄政申请陈情**与**君心参悟追问**两个高级场合未定配额。三场合是否共享配额、摄政位玩家是否上浮，直接影响预算模型——必须在成本建模前定稿。
- **策划侧未意识到的一点**：L3 是公开的成长目标。当"每日 3 次对话"成为身份象征时，**限频本身就是体验的一部分**（进阶特权感），建议文案上正向包装，而非默默限额。

### 策略 2：人格卡 + 检索增强（RAG）降 token —— **可行（附条件）**

- 可行性：成立，且是本项目的标准做法。人格卡为静态文本（每君主 2-4K token），使用**供应商级 Prompt Caching**后命中成本约为原价 10%-25%；七国人格卡天然适合缓存。
- RAG 部分（国史/对话摘要缓存）实现为：决策时检索"相关记忆摘要"注入 prompt，摘要由**异步摘要流水线**批量生成（走批处理价）。
- **条件**：①摘要生成本身有成本与延迟，需挂到旬度批处理而非实时；②摘要质量需**双审**（机器+人工，对齐风险登记册 #1），否则人格一致性随摘要漂移劣化——"低成本检索"检索回低质量记忆，比不检索更糟。
- **架构坑**：人格卡是唯一权威源（GDD 4.1），意味着人格卡**每次改版都会击穿全部缓存**。人格卡需版本化管理，改版集中触发批处理重建缓存，避免常态性缓存失效。

### 策略 3：短句先回 + 长文异步两级队列 —— **可行（附条件）**

- 可行性：成立。一级队列为同步流式输出（≤1-2 句，先营造"君主在场感"），二级为异步补全长文，推送回玩家。
- **条件（体验，非技术）**：短句与长文必须**风格连续**——玩家先收到"嗯？"再收到大段诏书是可以接受的；先收到一句问候、长文却答非所问则不可接受。工程上用**同一次会话状态**驱动两段生成，而非两次独立调用。
- **需 UX/策划定义**：长文异步到达时在 UI 上的呈现形态（诏书送达仪式感，正好契合视觉锚点②竹简帛书 UI——异步长文以"诏书送达"呈现，技术限制转化为仪式感，这是策划侧的机会点）。
- 需要防呆：玩家在长文未返回时发起新对话，需定义会话排队/覆盖规则（建议：新对话使未返回长文作废，prompt 中标注"上书未答即再谏"由人格化处理）。

### 策略 4：旬度决策批量批处理 —— **可行，且应再进一步（本评审最重要的建议）**

- 可行性：成立。每服 7 君主 × 每旬 1 次 = 每日约 2.3 次核心决策调用（含复盘语录），走供应商 **Batch API（通常 5 折）**，是全部策略中成本收益最大的一条。旬 = 3 天，批处理窗口充裕。
- **架构坑 1（时序窗口）**：旬切换是全服固定时刻，四层输入（国力仪表盘/玩家行为聚合/外交事件流/历史引力）必须在快照点**冻结**。批处理窗口 = 快照 → 生成 → Schema 校验 → 落库 → 下发，需预留 30-60 分钟并设计**降级链**（主模型失败→备用模型→冻结上旬诏令+GM 注入），否则一次 LLM 故障就打破"每旬必有国策诏"的核心节奏承诺。
- **架构坑 2（事件决策与旬决策竞态）**：旬窗口内发生的事件决策（宣战/天灾/刺杀）与即将生成的旬决策可能矛盾（如宣战后 1 小时，旬诏却发布和平目标）。需**决策版本化**（旬号 + 序号）与优先级规则（事件诏令覆盖旬诏冲突项）。此规则 GDD 未定义，需策划侧补。
- **重要建议（超出 GDD 的成本分水岭）**：**任务潮不应由 LLM 逐条生成**。GDD 说"任务潮按国力短板加权生成"——这天然是**规则引擎**的活：五维数据 → 短板判定 → 任务模板库加权抽取 → 产出结构化任务池（数值可控、可审计、零 LLM 成本）。**LLM 只负责：(a) 在任务池中做本旬主推方向的权衡；(b) 生成《国策诏》叙事文本与复盘语录**。这一拆分同时解决成本（LLM 调用量降一个量级）、数值失控（GDD 风险 #8 主导策略涌现）、审计（任务数值是确定性产出）。建议 GDD 4.4 第 4 条按此补注。

### 策略 5：预算熔断 + 降级为结构化选项 —— **需调整**

- 可行性：成立。实现为 LLM 网关层的**实时计量与分级熔断**（按服/日预算，token 级记账），技术上无难度。
- **架构坑（降级资产本身是隐性成本）**："降级为结构化选项"意味着每个对话场合都要有**预生产的结构化模板库**（如君心参悟的降级版 = 从预设语录库检索的问答），这是一批需要文策侧生产的资产，且要覆盖 7 国人格 × 3 场合 × 常见主题。**未备好模板库，熔断时降级将不可用**。建议模板库作为 V1 资产清单立项。
- **体验断裂**：付费感强的 L3 玩家某天突然发现自己从对话降为选项，若无声降级则损害"君主是活的"支柱。建议降级本身做**叙事包装**（"寡人今日倦于言语，有事上书"），由 LLM 前一旬预生成一批降级话术。需策划侧定义降级形态的产品规格。

### 评审总表

| # | 策略 | 判定 | 关键补充 |
|---|---|---|---|
| 1 | ≤5% 覆盖 | 需调整 | 三场合配额归属需定稿；限频正向包装 |
| 2 | 人格卡+RAG | 可行 | 摘要双审；人格卡版本化缓存管理 |
| 3 | 两级队列 | 可行 | 同会话状态驱动；长文送达仪式化；对话覆盖规则 |
| 4 | 旬度批处理 | 可行 | 快照冻结+降级链；事件/旬决策版本化；**任务潮改规则引擎生成（重大建议）** |
| 5 | 预算熔断 | 需调整 | 降级模板库需立项生产；降级叙事包装 |

### 2.2 决策流水线（旬决策主路径 + 事件决策旁路）

**旬决策（每旬 1 次，批处理）**：

1. **输入聚合（快照冻结）**：A4 在旬快照点冻结四层输入（国力五维及环比、玩家行为聚合、外交事件流、历史引力参数），生成快照 ID，投递 B1。
2. **Prompt 组装**：B2 按君主人格卡（缓存命中）+ 硬记忆（恩怨账本确定性注入：通缉名单、关键恩怨）+ RAG 检索的软记忆摘要 + 本旬快照，组装 prompt。
3. **LLM 推理**：B3 走 Batch API 批量执行 7 国；输出强制 JSON Schema（国策诏条目、主推方向引用任务池 ID、复盘语录、事件处置意向）。
4. **结构化校验**：B5 校验 schema 合法性 + 业务规则（任务 ID 必须存在于任务池、数值范围、五维声明与模板一致）+ 护栏文风过滤；失败进入修复重试（≤2 次），仍失败走降级链（备用模型 → 冻结上旬 + GM 注入）。
5. **落库**：决策连同**完整证据链**（快照 ID、prompt 版本、记忆引用 ID、输出原文）写入 C1，状态机 `PENDING → VALIDATED → PUBLISHED`。
6. **下发**：A1 在旬切换点按旬号原子拉取 PUBLISHED 决策；A3 依据主推方向生成任务潮；诏令与语录下发客户端。

**事件决策（宣战/停战/会盟/天灾/刺杀/叛逃等，旁路）**：领域事件经 C4 到达 B1 → 同流水线但走**同步小窗口批处理**（SLA 分钟级）→ 产出事件诏令（决策版本 = 旬号 + 序号，事件序号更高，覆盖旬诏冲突项）。

**自由对话（3 个高级场合，旁路）**：同步流式路径，独立于上述流水线；令牌桶限频 + 会话记忆（Redis）+ 两级队列（短句流式 / 长文异步回推）；预算熔断时降级到模板库（策略 5）。

### 2.3 护栏层位置（明确回答"放哪一层"）

护栏放在 **B4，AI 决策服务内部，作为 Prompt 组装前后的双向流水线**，部分能力下沉到 B3 网关：

| 护栏 | 位置 | 时机 |
|---|---|---|
| 输入净化（注入攻击防御：玩家上书文本中嵌入指令、越权索求） | B4 前置 | Prompt 组装前，对玩家自由文本做标记隔离与规则检查 |
| 人格锚定（人格卡注入 + 人格偏置权重校验） | B2+B4 | 组装时注入；校验时对照人格卡反向核查输出风格倾向 |
| 文风过滤（现代话语检测、敏感词库、合规红线） | B4 后置 | 结构化校验阶段，命中即修复重试或打回 |
| 预算熔断（token 计量、分级降级） | **B3 网关层** | 每次调用的网关侧记账与路由，业务代码无感知 |
| 越权校验（摄政不可干预 AI 独占项：宣战终裁/人格卡/历史引力等） | B4 后置 | 结构化校验：决策引用权限域做白名单核查 |
| 合规终审（语录入库前机器+人工双审） | B4 产出侧 | 异步队列，对齐风险登记册 #3 |

设计原则：**护栏必须能否决决策**（修复重试 → 降级 → 拒绝），而非仅告警；所有护栏动作本身写入 B7 透明日志可复盘。

### 2.4 关键横切关注点

- **透明日志规模（GDD 4.3 需策划知悉）**：每旬每国约 3-10 条决策 + 摄政行为 + 廷议全记录，含完整证据链。估算单服约 5-20 MB/日（含 prompt 证据链），赛季（12 周）约 0.5-2 GB/服——**存储本身可承受**，真正的坑是：①不可变审计存储 vs 玩家隐私（删号权）冲突，需"赛季内全透明 + 跨赛季匿名化归档"（见 §5 调整项 3）；②证据链中 prompt 含玩家上书原文，需脱敏规则。
- **AI 记忆跨赛季**：硬记忆（恩怨账本结构化表）跨赛季**全量保留**；软记忆（对话/事件摘要）赛季末由 B6 摘要流水线压缩归档（走批处理价），下季按需 RAG 检索。方案详见 ADR-003。
- **史书生成**：赛季末批处理任务，输入 = 透明日志 + 决策库 + 大事记时间线，产出《本服史书》初稿后人工终审。素材天然齐备是本架构（事件溯源 + 全证据链）的副产品红利。
- **跨服复用**：B 层（AI 决策服务）全服共享一套部署，按服隔离租户——AI 成本不随开服数线性倍增运维；A 层严格分服。

### 2.5 成本模型粗估（供预算讨论，非承诺）

以一服 1 万 DAU、旬 3 天计：
- 旬决策：7 君主 × 8 次/日折算 ≈ 每旬 7 次批量调用（每次 30-60K token 含快照与记忆），Batch 价 5 折——**可忽略量级**。
- 事件决策：假设每旬 20-50 次，同量级可忽略。
- **自由对话是唯一大头**：1500 次/日 × 每次 2-8K token。全预算的 80%+ 在此，故策略 1/3/5 全部围绕它。
- 摘要流水线：旬度批处理，量级可忽略。
- 结论：**成本模型的敏感变量只有一个——自由对话次数 × 平均上下文长度**。建议运营侧建监控大盘盯这两个数。

### 2.6 文武体系架构影响（ARCH-002 修订）

> 对齐 GDD-0 v0.2：官职分文臣/武将两路、散阶八档 + 稀缺席位（相邦/司徒/太史/行人/上将军/司马/尉）、无职业锁定人人可学所有技能（熟练度 + 任官实践解锁）、"文臣定策→君主裁定→任务池转译→武将执行→策功/事功双轨归因问责"闭环、转路为重转换（降 1 档 + 3 旬冷却）、摄政候选须曾任大夫档以上。
>
> **评估结论：架构骨架（A/B/C 三层、决策流水线、ADR-001~003）无需变动。影响集中于三点：事件 schema 归因链字段（必须现在冻结）、官职数据模型、结算校验。其中归因链字段属于"现在不做、以后补不回"的技术债。**

#### 2.6.1 策功归因链的事件溯源需求

- **归因链路**（全链路事件化，每环一个领域事件）：
  `方略提交(ProposalSubmitted) → 君主裁定采纳(ProposalAdopted) → 诏令发布(DecreePublished, 旬号+序号) → 任务池转译(TaskGenerated, 规则引擎 A3) → 任务完成(TaskCompleted, 携带国力 delta) → 归因回写(AttributionWriteback → 策功/策罪、事功)`
- **核心要求：全链路因果字段**。每个领域事件必须携带 `trace = { proposal_id, decree_id, task_id, 旬号, 赛季号 }` 的可用子集（必填：旬号+赛季号；上游 ID 逐级透传，无来源则显式标记）。落地要求：
  - **A3 任务规则引擎**产出任务时必须打来源链标签（诏令 → 方略）；无方略来源的任务（如 AI 内政）标记 `origin=AI_INTERNAL`；
  - **A1 结算服务**的国力变化事件必须带来源标签入库；C1 建**归因视图表**（按 proposal_id 聚合"采某卿之议"的实际国力效果）——这是策功结算、史书《名臣列传》、君主复盘问责语录三者的共同数据源。
- **对消息总线/事件 schema 的影响**（补强 ADR-002 后果③，见 ADR-002 修订注）：
  - **事件 schema 治理前移**——归因字段必须是 MVP 事件 schema v1 的必填结构。事后追加将导致历史数据无法归因、列传叙事出现断层；
  - 归因消费链是**只追加（append-only）聚合**，与既有"按国家分区键有序消费"模型兼容，无需新增总线拓扑；归因回写为旬度批量结算（走批处理，非实时），实时性要求仅到"下一旬复盘前可查"。
- **架构坑（多来源叠加）**：GDD 六定义"国力增长 = 玩家任务贡献聚合 + AI 内政决策"——策功归因的**分母歧义**是本修订最大的规格缺口：一诏令转译多任务、一任务多玩家贡献、收益递减叠加、AI 内政同步扰动。架构只能保证链路可追溯，**"归多少"的规则必须策划定义**（见 §5 调整项 8）。

#### 2.6.2 散阶/席位/履历/熟练度/转路冷却的数据模型要点

- 落位为 **A6 官职与履历域**（新子域，不散落玩法域），核心表：
  - `散阶表`：玩家 × 路（文/武）× 阶位（八档）× 晋升旬号；文武双阶并存（双修合法，转路时另一路按履历重就 + 降 1 档）。
  - `席位表`：每国每席位一行，字段含 `现任玩家ID、任期旬号区间`。**席位稀缺性 = 数据库级锁**：任命走单事务 + `UNIQUE(国家ID, 席位ID, 任期旬号)` 约束 + 现任行级锁，并发竞争任命由 DB 约束兜底（应用层判断会竞态）；任命/免职经 **Outbox 模式**发布事件，防 DB 与消息总线不一致。
  - `履历表`：任官记录（席位、旬号区间、路向）+ 策功/事功账本。它是四个下游的**唯一权威源**：摄政资格（曾任大夫档以上）、跨季声望遗产加权、AI 君主"出身偏好"差异化态度、史书《名臣列传》。
  - `熟练度表`：玩家 × 技能 × 数值 × 加速来源（任官/实践）。
- **转路冷却（降 1 档 + 3 旬）**：冷却以**旬号为锚**而非墙钟（`转路旬号 + 3 ≤ 当前旬号` 才可再转），天然免疫停服维护与多机时钟漂移；转路是状态机事件（记录降档前后阶位，可复盘）；与"择木而栖"30 天冷却统一挂到**冷却注册表**（同一机制、两类冷却类型）。
- **席位权重与旬快照的跨域一致性**：席位影响 AI 决策权重面（司徒增民生议题权重、太史增历史引力话题可见度）→ 席位变更事件必须同时被 B2（prompt 组装的决策权重快照）与 A2（政治域权限）消费；A4 旬快照冻结时**在任官职状态一并冻结**，规则建议"快照时点在任者生效"（旬内换帅，本旬决策仍按旧权重——需策划确认此语义，见 §5 调整项 10）。

#### 2.6.3 熟练度"任官实践解锁"的结算校验要求

A1 任务结算服务在发放熟练度/加速时，强制服务端校验：

1. **任官经历校验**：查 A6 履历表（Redis 缓存 + 任官/免职事件同步失效 + 事件异步补偿双通道——不能只靠总线异步，否则免职瞬间存在加速窗口）。
2. **高位熟练度解锁只认证据链**：只认**携带在任标记的实践事件**（任务完成事件含该玩家任官上下文），脱离任官的纯刷取不加速——这是 GDD"官位稀缺 + 熟练度门槛 + 履历资产"三重防同质化中第二重的技术落地。
3. **转路冷却期规则**：冷却期内离任一路的任官加速应失效（防绕过重转换成本），需策划确认（归入 §5 调整项 9）。

#### 2.6.4 本修订的技术风险结论

**无新增阻塞级技术风险。** 归因链字段冻结、席位 DB 锁、履历权威源三项均在现有架构模式（事件溯源 + ADR-002 + C1 PostgreSQL）内消化；需要策划侧跟进的规格缺口见 §5 新增调整项 8-10。

### 2.7 玩家开放 API（客卿代驾）架构（ARCH-003 新增）

> 用户已拍板：玩家可将自有 LLM/AI 通过 API 接入游戏，代理文官路线（策略/上书/议政）或武将路线（任务执行/会战操作）。设计侧并行产出 GDD-S7《客卿代驾》（知识边界/限频需求清单回传中）——本节先行按架构专业判断定技术骨架，配额等接口参数待 GDD 定稿后回填（见 §5 调整项 11-14）。

#### 2.7.1 接入模式：玩家拉取-提交（BYO-Agent），服务端不碰玩家 LLM

```
玩家侧（自费）：玩家 Agent ──调用玩家自有 LLM（服务端不感知、不经手、不担责）
                    │  ↑ 拉取：决策上下文包（服务端渲染的结构化数据，只含 UI 可见信息）
                    │  └ 提交：结构化动作（白名单 schema）
┌───────────────────┴────────────────────────────────────────────────┐
│ A7 玩家开放 API 网关（A 层新组件，ingress 方向）：                    │
│  · 鉴权：API Key ↔ 账号/角色绑定 + 路线 scope（文官/武将）+ 可撤销      │
│  · 限频：四层令牌桶（Key / 账号 / 风控簇 / 路由）                       │
│  · 校验：动作白名单 schema 强校验 + 幂等键 + 动作序号                   │
│  · 上下文包渲染器：复用 B4 净化库，"UI 可见信息超集"渲染                │
│  · 审计：全部动作入透明日志，事件打 agent_source=PLAYER_API             │
└─────────────────────────────────────────────────────────────────────┘
```

- **为何不用"服务端回调玩家 LLM"模式**（备选，远期评估）：服务端持有玩家 API Key 有保管与合规责任、回调延迟与可用性污染决策流水线、成本归属混乱。拉取-提交模式下**玩家 LLM 成本 100% 玩家自付**，服务端只承担上下文包渲染 + schema 校验 + 审计（量级与普通 UI 请求同级）。
- **信息平等原则（信息边界的正面表述）**：玩家 Agent 能拿到的信息 = 该账号在 UI 上可见信息的**超集（恰好等于）**——不多给一条。上下文包是"UI 可见数据的机器可读渲染"，不是新情报通道。

#### 2.7.2 安全专题清单（缓解措施 + 责任边界）

**"作弊"的架构定义（ARCH-004 修订）——框架内自由是默认态，拦截只针对以下五类**：

| # | 作弊类 | 定义（越线判据） | 技术检测点 |
|---|---|---|---|
| C1 | **越权动作** | 白名单外动作；确认级不足的自动执行；身份性动作（择木而栖/转路/投票/摄政提案/兵符统领——S7 反目标 A6"政治人格"行为）被代行 | 网关 schema 白名单拒绝；**确认矩阵服务端强制**（required_confirm 为动作白名单内数据驱动字段，客户端不可改） |
| C2 | **知识边界突破** | 请求包外数据、上下文探测模式（高频拉取、字段枚举式访问、包内容差异探测） | 上下文包渲染器唯一出口白名单（§2.7.1 信息平等）；拉取频率画像 → K6 特征上报 |
| C3 | **身份伪造** | agent_id/player_id 伪造；冒充手操（隐藏 AI 来源）；叙事冒充（诏令体/君主自称/他人口吻） | agent_source 由事件生产者服务端写入（网关不可传）；双 ID 绑定校验；文风过滤器反向拦截 |
| C4 | **归因污染** | 农场小号稀释递减/归因；双 ID 流水不一致；公平性带宽（S7 §8.1）异常突破 | 风控簇聚合 + N4 递减；审计流水双 ID 一致性校验；声望速率/采纳率分群监控 |
| C5 | **资源竞态** | 重放、并发劫持、会战窗口操作洪流 | 幂等键去重 + 单调动作序号 + 乐观并发版本 + 会战专属冷却（≥10s，过载保护定位） |

**拦截哲学**：五类之外一律放行且不做任何标记性惩罚（无"AI 使用耻辱"机制——用 AI 不隐藏，S7"代拟印鉴"是透明而非污点）；五类的处置链：限速 → 冻结客卿自动化 → GM 审（处置是安全动作，不是玩法惩罚）。下方六项威胁清单是五类定义的展开（叙事冒充归入 C3，限频绕过归入 C1/C4 的手段面）：

| # | 威胁 | 缓解措施 | 责任边界 |
|---|---|---|---|
| 1 | **提示词注入/越狱**：玩家叙事文本（上书理由/会战喊话）内嵌指令，试图套取君主决策权重或操纵君主决策 | ① **玩家自由文本永不直入君主决策 prompt**——进决策流的只有去重统计（petition_tendency 计数）与结构化事实字段；君主语录引用上书走"引其意不引其名"且只引用机器摘要；② 上下文包由服务端字段化渲染，无自由拼接 prompt 面；③ 叙事字段过 B4 净化层（长度上限+标记隔离）后才可被展示 | 服务端强制（架构性排除）+ B4 净化 |
| 2 | **情报套取**：API 比玩家手动挖到更多内部数据 | 信息平等原则（§2.7.1）+ **情报边界白名单**——以下数据**永不出服务端**：人格卡内部字段（style_weights/speech_profile/gm_overrides）、决策 judgment_basis 数值细节、恩怨账本内部值（intensity/状态机）、GM 参数、他人上书者身份（"引其意不引其名"）、透明日志中他人的脱敏内容（对 API 同样脱敏） | 服务端强制（上下文包渲染器唯一出口，白名单字段构建） |
| 3 | **限频绕过**：多 Key、泄漏 Key 共享 | 四层令牌桶（Key→账号→风控簇→路由）取最严；Key 异常行为检测（IP 跳变/行为模式突变告警）；Key 泄漏可一键撤销且全量审计可回溯 | 服务端强制 |
| 4 | **多账号 API 农场**：小号矩阵代驾刷国力/刷策功 | ① 复用 N4 风控簇聚合（同设备/指纹簇计同一递减序列——农场收益天然被 r=0.7 递减+40% 占比上限压制）；② Agent 声明指纹（agent_id 必填）+ 同簇行为相关性检测；③ 恩怨/履历/席位按国隔离；④ 摄政与席位**权限动作禁止 API 代驾**（默认，待 GDD 确认） | 服务端强制限频+风控；封禁为人工事后追责（GM 依审计） |
| 5 | **重放与竞态（会战窗口全自动）** | 每动作强制幂等键（client_request_id 去重）+ 每 Key 单调动作序号（乱序拒绝）+ 节点推进提交带乐观并发版本（expected_state）；**会战窗口 API 专属更低频控 + 指令冷却**（数值待 GDD，§5-14）；重放样本全量审计留痕 | 服务端强制 |
| 6 | **叙事冒充**：代驾文本冒充其他玩家口吻或君主口吻，污染"君主是活的"叙事 | 展示层对 API 来源叙事强制"客卿代笔"来源标记；君主口吻词式样由 B4 文风过滤器反向拦截（玩家文本不得使用诏令体/君主自称） | 服务端强制 + 透明日志事后追责 |

#### 2.7.3 对现有架构的影响评估

1. **消息总线/透明日志/Spike ③ 事件 schema：必须预埋 `agent_source` 标记——本评审明确建议"是，且为必填枚举字段（非 extensions 可选项）"**。枚举值 MVP 起 `HUMAN_UI | PLAYER_API`（远期扩展 GM_TOOL 等）。理由：API 玩家行为与手操行为若不区分，事后审计、农场检测、代驾公开标记、策功/事功的来源治理全部无法回溯——**事件 schema v1 冻结必须包含此字段，冻结动作不可先于本字段定稿**（直接联动 Spike ③ 排期，见 spikes.md v1.1）。`trace` 结构同步扩展：`agent_source` + 玩家声明 `agent_id`（可空）。
2. **A 层新增 A7 子域**（玩家开放 API 网关，§2.7.1），护栏复用 B4 净化库；对 B 层零改动——君主的决策流水线不感知动作来自手操还是 API（除 agent_source 随事件流转）。
3. **策功/事功双账**：API 代驾动作照常入账（双链同源不受影响），agent_source 随 delta_events 流转；履历表增加"代驾履历"可区分维度（摄政考评是否区分代驾贡献 → 待 GDD，§5-12）。
4. **MVP 范围建议**：MVP 仅做**schema 预埋 + 鉴权框架占位**（约 1 个 Story），玩家 API 全量功能放 V1——理由：MVP 12-16 周已满载、GDD-S7 未定稿、且 MVP 的 A/B 验证（齐摄政 vs 秦楚对照）不能引入自动化变量。此项需主理人确认。
5. **成本模型**：玩家 API 不增加服务端 LLM 成本（玩家自付）；服务端新增成本为上下文包渲染与审计存储，与普通 API 流量同级，配额收敛后可忽略。

#### 2.7.4 托管简化（四级 → 两级）的架构影响（ARCH-004 修订）

设计侧正将 GDD-S7 K4 托管分级 L0-L3 四级简化为两级（**辅助 / 全权**）；架构侧配套转向如下：

- **状态机二元化**：`ASSIST（辅助）` / `AUTONOMOUS（全权）`。辅助 = 上下文包推送 + 逐条人工确认后提交（原 L0/L1 合并，"游戏内建议"并入辅助级的 UI 面）；全权 = 白名单低危动作自动执行（原 L2/L3 合并，去受额与在朝时段）。
- **确认矩阵与档位解耦（本次简化的最大架构红利）**：每动作的 `required_confirm`（低危自动 / 高危强制确认 / 身份性禁代行）是**动作白名单表的数据字段**，档位只决定"自动执行是否可用"，不参与确认推导——服务端强制、客户端不可改（C1 检测点）。收益：两级之外未来想加任何中间档，**零代码变更、纯配置**。
- **降级链简化（采纳"冻结→回退手动"建议）**：全权级维持心跳（10 分钟）；心跳超时 → **冻结客卿自动化**（在途动作转"待办笺"人工处理，冻结不清零）→ 玩家手动接管一键可达。**移除原 L→L1→L0 逐级降级状态机与逐级叙事通知**（降级叙事保留单级："客卿告病，诸事躬亲"）。辅助级无心跳（逐条确认天然在线），K7 断连逻辑仅服务全权级——服务端会话状态显著简化。
- **实现项移除清单（待 GDD-S7 v2 回写确认后执行）**：① `daily_quota/quota_used` 每日额度强制逻辑与"额度冻结"；② `active_window` 在朝时段强制与"时段外积压"语义（字段保留，转玩家自设提醒，非服务端强制）；③ K7 逐级降级状态机（L→L1→L0）；④ 监控项"在朝时段合规率"与"L3 依赖度 ≤60%"（S7 §8.2）。**保留项**：`trust_credit` 信用分（防作弊专用，与托管档位彻底解耦）；"待办笺"承接容器（语义从"时段外积压"改为"冻结期积压"）；高危动作确认卡。
- **对既有 Story/spike 的影响**：mvp-epics 中客卿相关 Story 仍按"MVP 仅 schema 预埋+鉴权占位"不变（简化降低的是 V1 工作量，约 -1 人周）；Spike ④ 验收标准同步修订（spikes.md v1.2）。

### 2.8 玩家主权原则的架构语义（ARCH-005 新增）

> 铁律（用户定稿）：**玩家手动自主决策的权限大于 AI 的权限**。三条推论：① AI 能做的玩家都能手动做，部分动作仅限手动；② 手动永远覆盖 AI 已提交的操作（未结算前可撤销/接管）；③ 玩家在线操作时其客卿 AI 自动化让位。

#### 2.8.1 适用域澄清（避免原则误用的关键）

玩家主权作用于**玩家域**——客卿 AI（玩家的私人 AI）代提交的动作。**AI 君主（国格 AI）的决策不在玩家主权范围内**：君主决策的制衡走 GDD 4.3 摄政机制（威望值/弹劾/AI 收印绶），那是一套独立的"AI 与人的权力关系"。两套关系不混用：**君主 AI 对玩家有权威（支柱一"君主是活的"），客卿 AI 对玩家是工具（玩家主权）**——若允许玩家手动覆盖君主决策，支柱一与摄政制衡同时崩塌。本节全部语义只覆盖玩家域动作（上书/议政/任务/会战操作等）。

#### 2.8.2 手动覆盖/撤销：统一动作状态机（扩展 ADR-002 模式，推论②）

玩家域动作复用 ADR-002 决策状态机的三态模式，扩展为：

```
SUBMITTED ──校验通过──→ VALIDATED ──结算──→ SETTLED
    │                      │
    │ REVOKE（直接撤销）     │ OVERRIDE（作废重提）
    ↓                      ↓
  REVOKED              SUPERSEDED ──新动作──→ SUBMITTED（新生命周期）
```

- **SUBMITTED（已提交待处理）**：玩家可**直接撤销（REVOKE）**——新增元动作 `ACTION_REVOKE`（携带 target_action_id），免费、无需理由、幂等。
- **VALIDATED（已入执行/计票队列）**：不可直接撤销，走**覆盖作废重提（OVERRIDE）**——元动作 `ACTION_OVERRIDE` 携带新动作 + `override_of` 引用原动作；原动作转 `SUPERSEDED`（**不删除、保留痕迹、透明日志可复盘**——本项目"不删除、标注、可追溯"原则的第三次应用，与 S1 事件诏令"已因时事更易"同构）；重提受玩法节拍天然约束（上书 1 次/旬/议题等）——**覆盖免费，节拍即限频**。
- **SETTLED（已结算）**：不可撤销/覆盖，仅按游戏规则修正（争议走 GM 通道）。
- **会战窗口特例**：动作结算密集，撤销窗口下限 = 指令冷却时长（≥10s，即自动化动作结算延迟 ≥ 冷却，保证冷却期内手动可覆盖）；逐动作类型的窗口联动表待 GDD（§5-16）。
- **幂等与审计**：REVOKE/OVERRIDE 本身走动作白名单 + client_request_id 幂等（同 target 重复 REVOKE 返回首次结果）；审计事件新增 `REVOKE` / `OVERRIDE` 类型；**事件 schema trace 扩展 `origin_action_id` + `superseded_by` 字段——纳入 schema v1 冻结范围（联动 Spike ③）**。
- **归因语义（归因链标记）**：被撤销/覆盖的 AI 动作**归因清零**（策功/事功双账零贡献，回收其对玩家倾向统计的影响）；动作流水终态来源以**最终生效动作**为准（AI 动作被手动覆盖 → 决策最终来源=手动，`agent_source=HUMAN_UI`），SUPERSEDED 痕迹仅供复盘不参与任何数值与统计。

#### 2.8.3 在线抢断（推论③）

- **会话级互斥**：玩家手动会话活跃（UI 在线且有操作）→ 该玩家客卿自动化通道进入 `SUSPENDED`：在途自动化动作在**结算前检查点**发现会话活跃即挂起（转"待办笺"或降级为建议推送）；会话空闲超时（建议 15 分钟，待 GDD）→ 自动恢复 AUTONOMOUS。
- **与心跳/冻结链整合**：优先级 **挂起（正常态）> 冻结（异常态，ARCH-004 降级链）**；挂起不扣 trust_credit、不消耗配额、不触发降级叙事（玩家在线本就是主权行使，不是客卿故障）。实现为 Redis 会话注册表 + 动作执行前置检查，锁粒度 = 单玩家，无分布式竞争。
- **不可逆豁免**：已结算部分（已消耗资源、已入推进度）不回滚——主权覆盖的是"未结算"域（推论②原文边界），只冻结后续。

#### 2.8.4 仅限手动动作（推论①）

- **确认矩阵扩展三值**（与 ARCH-004 数据驱动确认矩阵同构，纯配置扩展）：`authority: AUTO_OK | CONFIRM | MANUAL_ONLY`。
- MANUAL_ONLY 动作：API 通道提交即拒绝（C1 越权检测点，错误码区分"仅限手动"）；动作在上下文包中带 `manual_only` 标注（玩家 AI 可知边界，避免无效调用与反复试错）。
- 候选集合：S7 反目标 A6 全部身份性动作（择木而栖/转路/投票/摄政提案/外交缔约）+ 兵符统领 + 摄政权限动作；最终清单与 ARCH-004 第 15 项高危确认清单**合并定稿**（§5-16）。
- 推论①的另一半"AI 能做的玩家都能手动做"由架构天然保证：动作白名单对手操 UI 与 API 是**同一张表**（客卿不拥有手操没有的动作），manual_only 只做减法。

#### 2.8.5 离线授权（守舍）（ARCH-006 新增）

> 用户定稿：玩家不在线时可将一定权限下放给玩家自带的 AI。设计侧并行产出授权契约与权限分级，本节为架构支撑评估。

**1. 授权契约 = 服务端强制的权限上界对象**：

```
Contract = { allowed_actions[]  // 动作白名单的子集（manual_only 天然不可入）
           ; spend_limits        // 资源/声望支出上限（额度执行，见下）
           ; window              // 期限（旬号锚定，到期自动失效）
           ; halt_conditions[]   // 紧急停机条件（事件驱动，见下） }
```

契约由玩家提交参数、**服务端校验后构造并存储**（客户端永不可直接注入契约对象——伪造契约属 C1 越权）；契约缓存于 Redis（TTL 对齐期限），玩家随时可查看/修改/撤销（修改契约 = 手动动作，走确认矩阵）。

**2. 三态判定：网关在会话互斥锁语义上的扩展**。执行前置检查（ARCH-005 单点）从"查会话活跃"扩展为三段判定，优先级从高到低：

```
① 在线手动：玩家会话活跃（有操作）→ 自动化挂起（ARCH-005 抢断，最高）
② 在线全权：玩家在线、会话空闲窗口内 → AUTONOMOUS 全量执行（仅过载保护约束）
③ 离线授权：玩家不在线 → 按契约执行（契约 = 额度 + 动作子集 + 停机条件的交集）
   └ 无契约/契约过期/熔断中 → 不执行，转待办笺（ASSIST 建议仍可产出）
```

**改动点评估：无阻塞。** 现有 Redis 会话注册表（player_id → session_state/last_active_at）直接承载：①注册表新增 `contract` 键类型（Redis TTL 天然实现期限）；②执行前置检查从单查扩展为三段判定函数——改动集中在 A7 网关检查点一处，纯服务端逻辑；③"在线"判定沿用 2.8.3 定义（有操作即活跃/空闲超时恢复），离线 = 会话注册表中无活跃记录。**判定链与挂起/冻结优先级不变：在线手动 > 在线全权 > 离线授权（受契约）> 冻结（异常态）**。

**3. 额度执行（离线窗口的服务端强制）**：**扣减预检 + 结算对账**两段式——动作提交时预估支出（资源/声望）→ 原子预扣契约额度计数器（防并发竞态）→ 结算时按实际支出对账、差额回补。**超限熔断 ≠ 拒绝玩家**：触顶即自动化停止、在途动作转待办笺，玩家上线后处理——**额度是契约的终止条件，不是惩罚**：超限不扣 trust_credit、不进五类作弊检测（C1-C5）；但**绕过/篡改额度机制的尝试**（并发预扣竞态利用、伪造契约对象、双账号共享额度）属 C1/C4 作弊，正常检测处置。在线全权态不受契约额度约束（契约只在离线窗口生效），仅受全局过载保护。

**4. 紧急停机（halt_conditions）**：触发检测来源 = **事件总线订阅**（复用 NATS，独立消费组，不阻塞玩法消费者）：候选触发事件——本国被宣战事件诏令（S1 M4）、CRITICAL 短板首次触发与危机叙事事件（S2 N5）、重大恩怨事件（S1 M8）。命中契约停机条件 → 暂停自动化 + 转待办 + 停机原因入守舍报告。**响应时延要求：订阅到停机生效 ≤60s（p99）**——事件本身走 S1 分钟级 SLA，停机是保守动作，分钟级足够且避免误停震荡；超时告警接入 E7 监控。事件清单与停机条件的最终映射待 GDD（§5-17）。

**5. 守舍报告（离线动作 digest）**：**零新增存储**——复用透明日志 B7（玩家域动作本就全量审计，含 input/output_digest 可回放）+ 归因链 trace，按离线窗口聚合 `player_id + agent_source=PLAYER_API` 的动作摘要（动作类型计数 / 支出汇总 / REVOKE-OVERRIDE-SUPERSEDED 事件 / 停机记录 / 待办笺清单）。**回归推送 = 上线拉取**：玩家会话重新激活时按需生成"守舍回禀"数据接口（拉取模式对齐信息平等与成本模型；叙事化呈现——"客卿守舍，诸事如仪/有变待裁"——由文策定义）；可选每日定时批处理聚合（走批处理价）作为 V1 优化项。

**与托管两级的关系**：守舍 = AUTONOMOUS 的**离线子集**（契约是其权限上界），资格门槛建议 = 全权资格 + 额外信用期（比在线全权更严——离线窗口无人工兜底），由设计侧定稿（§5-17）。

### 2.9 高位离席与代理（架构支撑评估）（ARCH-007 新增）

> 背景：设计侧并行设计《高位离席与代理》系统（告假/次席代摄七折/失期收回/回归交割）。本节为架构承载评估，数值与阶梯参数待设计侧定稿（§5-18）。

**1. 离席状态机的架构承载：独立状态域，不挂会话注册表**。离席是**政治身份状态**（跨会话持久、旬级生命周期、全国可见），与客卿会话注册表（会话层、分钟级、个人域）是不同抽象层——放 **A2 政治域**扩展（摄政子域旁），状态机：`IN_OFFICE → ON_LEAVE(告假) → PROXY(次席代摄) → OVERDUE(失期) → REVOKED(收回) / RETURNED(回归交割)`。**告假/失期计时：服务端权威 + 旬号锚定，挂冷却注册表**（与转路 3 旬冷却同构，`离席旬号 + N ≤ 当前旬号`），免疫停服与时钟漂移。事件 `ABSENCE_STATE_CHANGED` 入总线（trace 完整，进 schema v1 冻结清单）。

**2. 代理摄政的权限代理语义：混合——决策权重面快照生效，权限动作面即时生效**：
- **决策权重面（seat_influence 对 AI 决策的影响）沿用"快照时点在任者生效"**：旬快照（A4）冻结的是状态与权重快照，代理转移在**下一旬快照**切换到代理者（七折系数 `×0.7` 作为快照字段标注）。理由：①旬决策 prompt 组装与回归重放依赖"快照自洽"——旬中切换权重会导致 prompt 与快照不一致且无法重放（破坏 M2 快照的复盘根基）；②旬延迟对权重面无损——权重影响的是旬决策的议题倾向，晚一旬体现完全可接受；
- **权限动作面（廷议发起权/任务潮优先级覆盖/封赏比例）即时生效**：这些是动作时校验（执行前置检查查当前有效权限持有者），天然即时；代理者发起的动作用 `delegate_scope=REGENT_PROXY` 标注；
- **例外：收回即时失效**——失期收回与威望耗尽下台是**安全动作**，权限立即失效（不等下一旬快照；快照语义让位于安全）。后果：收回当旬已冻结的快照中仍含旧权重（该旬决策按收回前状态生成）——可接受，决策产出不回滚，与"已结算不回滚"（§2.8.3）一致。

**3. 失期阶梯定时器：旬边界检查作业**。挂 E1.2 旬号时钟服务的旬作业编排器：旬切换作业流 = 快照冻结 → 旬决策批处理 → **失期检查**（遍历 ON_LEAVE/PROXY 状态，阶梯推进：告假超限→代摄；失期第 1 旬→警告；第 2 旬→收回，数值待设计侧）→ 赛季结算作业（仅赛季末旬，排序在失期检查之后——先定失期归属再结算政绩）。作业为幂等检查（重复执行无副作用），失败重试不推进阶梯（以作业执行记录为准）。

**4. 代理行为审计**：事件信封新增 `delegate_scope` 枚举（进 schema v1 冻结）：`NONE / REGENT_PROXY（代摄）/ OFFLINE_GUARDIAN（守舍，ARCH-006）`。二者语义区分：**代摄是政治身份的临时转移**（全国可见，透明日志"代摄印"，对齐 S7"代拟印"的透明哲学）；**守舍是玩家个人域的自动化**（个人可见）。归因规则：代理行为归**代理者本人** player_id（权责一致——"代行其权，即负其责"），离席者不享有代理期政绩也不承担其过错；`AGENT_ASSIST`（S7 §6.2）是流水标记位而非 delegate_scope 值，两层标记正交可并存（代理者用客卿代执行代理动作 → delegate_scope=REGENT_PROXY + agent_source=PLAYER_API）。

**5. 与玩家主权原则的关系（边界澄清）**：代摄动作属**政治权限动作**——按 §2.8.4 默认 MANUAL_ONLY/CONFIRM 级（不可入守舍契约自动执行）；次席本人也离线时代理链不自动延伸（无"代理的代理"），失期阶梯接管。被代理的高位者回归走"回归交割"（权限即时归还 + 代理期审计清单交付，交割语义=§2.8.2 OVERRIDE 家族的正式版）。

### 2.10 个人开发者部署形态（ARCH-008 新增，最高优先级现实约束）

> 用户定稿约束："我是个人开发者，负担不起游戏高额的运营费用。"原架构（Go 三服务+NATS+自建网关）为团队级方案；本节确立**个人开发者形态**，完整方案、成本模型与运维清单见 `solo-dev-architecture.md`。

- **推荐路线（一句话）**：单 VPS 轻栈——单 Go 单体二进制 + 同机 PostgreSQL(+pgvector) + 旬号 Cron + LLM 直连 SDK（配置切换）+ 对象存储备份；中性预估全成本 **¥60/¥151/¥378 每月**（30/100/300 CCU，基础设施+LLM 分列见 solo 文档 §5），年化 ¥0.7k~4.5k。
- **LLM 成本引擎核心结论**：旬决策在成本三个数量级之下（300 CCU 中性仅 ¥7/月），**真正的成本变量只有一个——自由对话人数 × 模型档位**；对策：模型分级（旬/事件/摘要全小模型，L3 对话中模型，强模型仅 ≤3 类白名单场景）+ 上下文硬上限 + 月预算封顶（超限自动 D3 模板化——最坏成本被结构性封顶）。旬周期 3→7 天使旬决策部分 ÷2.3（取舍归设计侧 GDD-S10）。
- **不变量（规模无关，不妥协）**：schema v1 冻结结构、旬号版本轴、决策状态机、事件溯源+Outbox 语义、硬记忆确定性注入、归因链、玩家主权三语义、降级链存在性（solo 下兼作无人值守保险）。
- **ADR solo 条款**：ADR-001~005 各补一行（见各 ADR 条目内"solo"标注）；**原决策逻辑全部保留**——降级的是实现选型，不是结构与语义；扩容触发器见 solo 文档 §7.3（CCU>500 拆分 / 队列积压换 NATS / LLM 费超阈建网关 / 多服开服回原形态）。
- **运维（单人生存清单）**：备份自动+每月恢复演练、healthchecks 死人开关、systemd 自启、旬作业降级链、赛季脚本化 dry-run；日常 ≤3h/周。

## 3. 基础 ADR

### ADR-001：LLM 提供方与调用模式

- **决策**：采用**多供应商云 API**（主流商业大模型），经自建 **LLM 网关（B3）** 统一抽象。三种调用模式：旬/事件决策走 **Batch API（异步批处理，约 5 折价）**；自由对话走**同步流式**；摘要/史书等离线任务一律入批处理队列。所有决策类输出强制 **JSON Schema 约束解码**，失败走 ≤2 次修复重试，再失败走降级链。
- **备选方案**：
  1. 自建开源模型（vLLM 部署）——初期否决：GPU 资本开支 + 7 国人格质量调优负担 + 精通中文先秦文风的模型能力差距；当自由对话量证明规模效应后可作为二期降本选项再评估。
  2. 单一供应商深度绑定——否决：价格谈判与供应连续性风险；本项目"君主语录"是核心资产，供应商中断即核心玩法中断。
- **理由**：旬决策天然可批处理（3 天窗口），Batch API 直接半价且 SLA 足够；自由对话要求秒级流式，只能同步；网关抽象使供应商可切换，并可集中实现计量熔断（策略 5）与护栏下沉。
- **后果**：①需投入网关开发（约 2-3 人周，含计量/路由/降级）；②供应商切换需回归"人格一致性测试集"；③数据出境与供应商数据协议需合规审查（玩家上书文本会进入 prompt）；④结构化输出修复重试消耗额外 token，预算模型需计入 1.3-1.5 倍系数。
- **solo 形态条款（ARCH-008）**：自建网关 → 单文件 LLM client 模块（重试/熔断/降级模板 ~300 行）；多供应商=配置切换；**模型分级 + 上下文硬上限 + 月预算封顶为强制项**（成本引擎见 solo 文档 §3）。

### ADR-002：AI 决策服务与游戏服的通信边界

- **决策**：**事件驱动为主 + 旬度定时快照为辅**的混合模式。游戏服（A）向消息总线发布领域事件；AI 决策服务（B）订阅消费（幂等）。旬决策由 B1 调度器在旬窗口触发快照式批处理；决策产出带**旬号 + 序号版本**，游戏服在旬切换点原子拉取 PUBLISHED 决策下发。一致性保证：决策状态机（PENDING→VALIDATED→PUBLISHED，迁移需护栏+校验双通过）+ 下发确认回执 + 超时降级（冻结上旬诏令 + GM 通道）。
- **备选方案**：
  1. 纯定时拉取（游戏服每旬 HTTP 拉取）——否决：事件决策（宣战刺杀）要求分钟级响应，轮询不满足；且拉取模式下输入聚合与游戏服耦合，B 层无法跨服复用。
  2. 全同步 RPC——否决：故障传染（LLM 抖动直接拖垮游戏服），且违背"护栏能否决决策"所需的异步余地。
- **理由**：事件驱动让"AI 记忆"天然由事件流驱动写入（叛逃事件 → 恩怨账本），与史书生成的素材采集同源；快照批处理规避了流式聚合的复杂度，把一致性锚定在"旬号"这一确定性版本轴上。
- **后果**：①引入消息总线运维（建议 NATS JetStream 起步，Kafka 留作规模化后迁移）；②所有事件消费者必须幂等 + 有序（按君主/国家分区键）；③事件 schema 是两域契约，需版本化治理，早期就要冻结演化规则；④"旬切换点"成为全服一致性锚点，快照冻结逻辑（A4）是单点关键路径，需重点测试；⑤（ARCH-002 修订）**归因链字段（proposal_id / decree_id / task_id / 旬号 / 赛季号 + origin 标记）必须作为事件 schema v1 必填结构随本 ADR 一并冻结**——文武体系的策功/事功双轨归因依赖全链路透传，事后追加将导致历史数据无法归因、《名臣列传》出现断层（详见 §2.6.1）。
- **solo 形态条款（ARCH-008）**：NATS JetStream → PostgreSQL 队列表（SKIP LOCKED）+ LISTEN/NOTIFY；Outbox 与业务同事务（一致性免费）；消费游标表替代消费者组；**决策状态机、旬号版本轴、版本化下发语义不变**（信封已冻结，扩容换 broker 零改动）。

### ADR-003：AI 记忆 / 恩怨账本存储方案

- **决策**：**混合方案，结构化表为唯一权威**。PostgreSQL 中建恩怨账本表（主体君主 / 客体玩家或国家 / 事件类型 / 严重度 / 旬号 / 赛季号 / 当前状态：记恨-通缉-释怀），由事件流驱动写入。**硬记忆**（通缉名单、叛徒、灭国之仇）在每次决策/对话时**确定性注入** prompt——不依赖检索，绝不遗忘。**软记忆**（朝堂对话摘要、事件氛围、君臣互动质感）由摘要流水线压缩为摘要表 + pgvector 向量列，供 RAG 检索。赛季末软记忆压缩归档，硬记忆全量跨季保留。
- **备选方案**：
  1. 纯向量库（全记忆 embedding 检索）——否决：向量检索是概率性的，"韩君最记仇"这类**硬人设承诺**不能靠概率召回——某次没检回叛徒记忆，玩家立刻识破"君主是假的"，直接击穿支柱一。恩怨的语义本质是结构化（谁/做了什么/多严重），不是模糊相似。
  2. 纯结构化表——否决：长程对话的叙事质感（"那次廷议上卿的谏言让寡人失眠"）无法结构化表达，缺了它君主就退化为事件处理器。
- **理由**：混合方案把"**必须发生**的记忆"（硬）与"**最好想起**的记忆"（软）分开治理，前者用确定性满足戏剧承诺，后者用检索满足叙事丰富度；决策证据链记录记忆引用 ID，玩家可在透明日志中复盘"君主为何记得我"，可解释性闭环。
- **后果**：①双写一致性：账本写入（事件驱动）与摘要产出（旬度批处理）节奏不同，prompt 组装时以账本为准、摘要只补充语境，需在 B2 明确优先级；②摘要质量决定软记忆成色，需人工抽检（对齐风险 #1）；③恩怨"释怀"状态机需策划定义（韩君记仇但总要有缓冲机制，否则恩怨只增不减导致 prompt 膨胀与叙事僵化）——**需策划侧补规格**。
- **solo 形态条款（ARCH-008）**：pgvector 保留（自装/托管 PG 均支持，零额外成本）；无向量条件时软记忆降级为结构化检索——硬记忆本就确定性注入，降级只损失叙事质感、不损失人设承诺。

### ADR-004：引擎与服务端技术选型（占位，评估框架先行）

- **决策**：暂缓，列出候选与评估维度，待技术验证阶段（Phase 3）定稿。
- **服务端候选**：① 自研 Go（+ NATS + PostgreSQL + Redis）——MMO 分服架构可控、并发模型契合、人才可得；② 自研 C#/.NET；③ 现有 MMO 框架（如 Skynet / pomelo 系）。
- **客户端候选**：Unity（MMO 常规、UI Toolkit 适合竹简文档型 UI、国内人才池）vs Unreal 5（画面上限高、但 MMO 网络与国风 UI 成本高）。
- **评估维度**：MMO 分服架构适配性；大量文档/卷轴类 UI 的生产效率；国内人才可得性；与 A 层（Go/C# 服务端）的团队技能重叠；中文社区生态与资产库；长线 5 年维护成本。
- **后果**：本 ADR 的悬而未决不阻塞 ADR-001~003——AI 决策服务与游戏服的边界已由消息总线解耦，客户端引擎选型不影响服务端架构。
- **solo 形态条款（ARCH-008）**：三服务 → **单 Go 单体二进制**（`internal/` 包分层 + 依赖方向 lint 强制，保持拆分能力）；客户端引擎倾向不变；扩容触发条件见 solo 文档 §7.3。

### ADR-005：玩家自接 AI（客卿代驾）的开放边界与治理（ARCH-003 新增）

- **决策**：采用**玩家拉取-提交（BYO-Agent）模式 + 独立玩家 API 网关（A7）**。玩家 Agent 从服务端拉取**决策上下文包**（服务端渲染、信息=UI 可见信息超集），自行调用玩家自有 LLM（成本玩家 100% 自付，服务端不经手不担责），再向服务端提交**结构化动作（白名单 schema 强校验）**。自由文本仅作为叙事字段，经净化后可展示但**永不进入君主决策 prompt**。限频四层（Key/账号/风控簇/路由）服务端强制；全部动作入透明日志并预埋 `agent_source=PLAYER_API` 必填标记；摄政/席位等政治权限动作默认禁止 API 代驾。
- **备选方案**：
  1. **复用自建 LLM 网关（B3）兼做玩家入口**——否决：B3 是"服务端出向调用 LLM 供应商"的 egress 网关，玩家 API 是"玩家入向调用游戏"的 ingress 网关，信任模型（零信任 vs 鉴权租户）、计量对象（token vs 动作）、失败语义完全相反；强行复用会把玩家不可信流量引入服务端 LLM 资金路径。两者共享的只有净化库与审计存储。
  2. **服务端回调玩家 LLM（注册 endpoint 模式）**——远期再评估：玩家 Key 保管责任与合规风险、回调延迟污染决策流水线、成本归属混乱；拉取-提交模式下全部不存在。若未来出现"玩家无运维能力但有 LLM 订阅"的明显需求，可加托管回调作为高级选项。
  3. **开放自由文本通道**（玩家 agent 直接与君主对话式交互）——否决：支柱一红线（自由对话仅限 3 场合的 GDD 定稿）、注入面不可收敛、成本失控；API 只开放结构化动作白名单，对话仍走玩家手动 L3 通道。
- **理由**：拉取-提交使玩家 LLM 成本与运维 100% 外置，服务端新增面仅上下文包渲染 + 校验 + 审计（量级同级普通 UI 流量）；信息平等原则把"API 情报优势"这一最大的公平性问题从规则问题降为架构问题（渲染器白名单构建，结构性保证不多给）；白名单 + 净化 + agent_source 三件套使注入、冒充、农场三类威胁的缓解是架构性排除而非行为封堵。
- **哲学注记（ARCH-004 修订：设计哲学从"限制使用"转向"框架内自由"——用户原话："只需要限制 AI 的权限，不让 AI 作弊，让 AI 在设定好的框架内自由发挥"）**：
  - **权限红线刚性不变**：知识边界白名单、结构化动作 schema、审计与 agent_source 归因标记——这四项是"框架"本身，永不放宽。
  - **限频四层结构保留（Key/账号/风控簇/路由），定位从"防依赖"改为"防作弊 + 防过载"**：过载保护优先于行为矫正——限频的存在理由是保护服务端，不是矫正玩家行为。
  - **关键区分：玩法节拍 ≠ 限频**。上书 1 次/旬/议题、议政 2 次/旬等约束来自游戏规则本身（旬制节奏、单玩家影响 ≤5% 防操纵），对 API 与手操一视同仁、**永不放宽也永不加倍**；"框架内自由"指的是技术调用速率的宽松，不是玩法节拍的绕过。
  - **宽松默认建议值（ARCH-004，供 GDD-S7 v2 标定或推翻）**：

    | 维度 | 旧建议（防依赖，ARCH-003） | 新建议（防作弊+防过载，ARCH-004） |
    |---|---|---|
    | 全 API 动作总量 | ≤120 次/时/Key | **≤1200 次/时/Key**（过载保护上限，10 倍放宽） |
    | 任务接取/执行调度 | 10/20 次/日额度 | **移除日额度**，技术上限 ≤100 次/时/Key |
    | 会战窗口动作 | 6 次/日额度 + 冷却 ≥30s | **移除日额度**，冷却放宽至 **≥10s**（防竞态主责移交幂等键+乐观并发，频控仅为过载保护） |
    | 玩法节拍类约束 | — | **不变**（上书/议政/投票节奏 = 游戏规则） |
    | 在朝时段/每日额度（原 L3） | 4h/日声明时段 + 40 动作/日 | **取消**（见 §2.7.4 移除清单），可保留为玩家自设的提醒功能 |

- **后果（ARCH-004 增补）**：⑥限频表按上表重写后，GDD-S7 v1 §4.1 白名单表中的保守限频列（1 次/旬/议题保留为玩法节拍；10/20 次/日、6 次/日、4h 在朝时段）需设计侧回写；⑦托管分级四级→两级（辅助/全权）使 K4/K7 子域简化（详见 §2.7.4），已按简化后形态拆解实现项；⑧防作弊从"限频拦截"转为"五类作弊特征检测 + 处置链"（限速→冻结→GM 审），K6 异常判定特征集对齐 §2.7.2 五类定义。
- **玩家主权原则（ARCH-005 增补）**："框架内自由"的宪法条款：**AI 权限 ⊂ 玩家手动权限**——动作白名单两通道同表、manual_only 只做减法、手动覆盖/撤销与在线抢断语义见 §2.8。对 ADR-005 自身的影响：动作白名单表新增 `authority` 三值字段；事件 schema v1 冻结范围再扩（REVOKE/OVERRIDE 事件类型 + origin_action_id/superseded_by trace 字段）；玩家域动作复用 ADR-002 三态状态机。离线授权（守舍，ARCH-006）为该原则的延伸：**离线权限 ⊂ 在线权限**（契约 = 玩家自设的权限上界，见 §2.8.5）。
- **solo 形态条款（ARCH-008）**：独立玩家 API 网关 **V1 前不建**（MVP-0 仅 schema 预埋 agent_source，既定决策）；V1 用单体模块 + Caddy 反代实现；守舍契约/三态判定/五类作弊检测/玩家主权语义全部保留——它们是服务端逻辑，无规模依赖。
- **后果**：①事件 schema v1 冻结新增必填 `agent_source`/`agent_id` 字段——**冻结时点依赖本 ADR 定稿，Spike ③ schema 内容扩充（排期影响见 spikes.md）**；②A 层新增 A7 子域约 2-3 人周开发（V1 全量，MVP 仅占位）；③配额/冷却/托管等级等接口参数需 GDD-S7 定稿（§5 调整项 11-14），参数不定则网关限频表只能以建议默认值上线；④代驾公开标记（"客卿代笔"）需要 UI 与文策侧配合呈现；⑤新增审计负担：API 动作全量入透明日志，存储增量按配额规模估算（可忽略量级）。

### ADR-006：终局身份——托管 Auth + 渐进式认领（ARCH-010 新增）

> 背景：试玩版（liguoce-trial）已上线正式登录——WorkBuddy 云服务 Auth **双通道**（手机验证码 OTP + WorkBuddy OAuth），players 表增 `owner_id TEXT DEFAULT auth.uid()` 与**行级安全（RLS）**：公开读 / 本人写（本人 = owner_id = auth.uid()），旧游客行 `owner_id IS NULL` 可被认领；观政模式（未登录只读入场）由同一"公开读"策略天然承载。

- **决策**：终局（正式服）身份体系采用**托管 Auth（WorkBuddy 云服务）双通道 + 渐进式认领**：①手机验证码 OTP 为主通道（国内触达无门槛、无邮箱渗透率问题）；②WorkBuddy OAuth 为辅通道（平台内用户一键登录）；③本地匿名游客会话保留为**第零态**（试玩即玩、零注册门槛），游客数据经 `owner_id` 认领升级为正式账号。行级安全（公开读 / 本人写）在**数据库层强制**，应用层不重复实现授权判断——BFF/网关与客户端直连共享同一授权面，消除双实现漂移。
- **备选方案**：
  1. **仅邮箱注册**——否决：国内玩家邮箱渗透率低、验证邮件到达率与时效差，注册发生在试玩转化的首屏即流失点；邮箱可留作远期补充 provider（枚举式扩展，不动 schema）。
  2. **仅第三方 OAuth（微信/QQ 等）**——否决：单一渠道依赖 + 个人开发者的过审与合规负担；WorkBuddy OAuth 已覆盖"一键登录"核心诉求。微信/QQ 等留作正式运营期按需增列。
  3. **自建账号密码体系**——否决：密码存储、找回、撞库防护、短信网关全自担，是个人开发者最差的维护面选择；托管 Auth 把这块风险整体外移。
- **owner_id 渐进认领的安全边界（本次决策的核心条款）**：
  1. **认领资格**：仅 `owner_id IS NULL` 的行（纯游客数据）；认领动作必须发生在本人登录会话内——写入走数据库默认值（`DEFAULT auth.uid()`）或受 RLS 约束的 UPDATE，客户端**不可指定**认领他人行；
  2. **已有主之行不可认领**（RLS 拒绝）——结构性排除"抢号"攻击面；
  3. **认领不可逆**：owner_id 一经写入不接受清空——防"认领-退出"横跳污染审计与恩怨链；
  4. **数据全额继承**：游客期产生的行为数据认领后全额归属，审计链（含 player_actions）与归因不变——身份升级不重置历史。
- **后果**：①玩家身份从"会话内 ID"升级为"跨设备持久身份"，为观政模式、stratum 玩家分层（TASK-010）、客卿 BYO 绑定（ADR-005 的 API Key ↔ 账号绑定自此有正式锚 owner_id）、守舍契约的身份判定（§2.8.5）提供统一身份根；②托管 Auth 引入平台可用性依赖——**退出预案**：players 表随时可整表导出迁移自建（手机号/标识字段掩码存放），托管是起点不是锁定；③双通道账号合并（同手机号既发 OTP 又绑 WorkBuddy）以 `(provider, identifier)` 唯一约束处理，试玩版已按此实现；④RLS"公开读"意味着所有玩家数据天然全国可读——**任何进入 players 的敏感字段（手机号原文、BYO 密钥）必须不落库**（客卿密钥仅存浏览器 localStorage，见 §2.7/ADR-005），这条红线由 schema 设计保证而非权限配置保证。
- **solo 形态条款（ARCH-010）**：托管 Auth 免自建短信网关与密码库，与单 VPS 轻栈正交（Auth 在平台侧、游戏服务端在 VPS 侧，凭 JWT 对接）；多 provider 扩展走配置不走代码。

## 5. 需策划侧知悉的调整项（跨成员一致性检查输入）

> （ARCH-002/003 修订状态注）v0.1 的 1-7 项经核对已回写 GDD v0.1/v0.2（任务池规则引擎、三场合独立配额、透明日志匿名化+留名史册、降级叙事包装、记忆硬/软拆分+负荆释怨线、诏书送达仪式化）✔；8-10 为文武体系修订新增，11-14 为客卿代驾新增，均待文策渊/GDD-S7 确认。

1. **任务潮生成机制改写**（GDD 4.4 第 4 条）：建议明确"任务池由规则引擎按五维短板加权生成，LLM 仅做主推权衡与《国策诏》叙事"。影响成本、数值可控性、审计三方面，是最重要的一条。
2. **自由对话三场合配额**（GDD 4.4）：L3 对话已有"每日 3 次"，但摄政陈情与君心参悟追问的配额未定义——共享还是独立、摄政位是否上浮，需定稿才能锁定成本模型。
3. **透明日志的隐私边界**（GDD 4.3）：建议"赛季内全国全程可查阅，跨赛季匿名化归档"；日志中玩家信息的脱敏规则需定义。"永久可查阅"在实现上与删号权冲突。
4. **降级形态产品规格**（GDD 4.4 第 5 条）：预算熔断后的结构化选项降级需要叙事包装与模板库资产；建议 GDD 补充"君主降级话术"设定。
5. **事件决策与旬决策的时序规则**（GDD 4.4）：同一旬内事件诏令与《国策诏》冲突时的覆盖/优先级关系未定义（本架构采用"事件版本号更高、覆盖冲突项"），需策划确认符合叙事逻辑（如宣战后旬诏不再谈和平目标）。
6. **恩怨状态机**（GDD 五）：AI 记忆"永久记住叛徒"需拆分为硬记忆（通缉等确定性保留）与软记忆（摘要可压缩）；并需定义释怀机制，否则恩怨单调递增会污染 prompt 与叙事。
7. （机会项，非调整）**长文异步送达的诏书仪式化**（GDD 4.4 策略 3）：两级队列的技术限制可转译为"诏书送达"仪式感，建议 UI/文案侧认领。——v0.1 修订已回写 GDD（信使送达+卷轴展开演出）✔
8. **策功归因分摊规则**（ARCH-002 新增；GDD 五·文臣路）：一诏令转译多任务、一任务多玩家贡献、收益递减、AI 内政同步扰动——"所倡方略对应的国力变化量"**归多少**的分摊口径未定义。建议：策功只归因本方略转译任务的直接贡献，AI 内政与其他方略贡献不计入。架构已保证链路可追溯（§2.6.1），但**分摊规则不定则策功数值无法结算**，阻塞策功/策罪闭环。
9. **转路成本文档口径统一 + 冷却期规则**（ARCH-002 新增）：用户定稿口径为"重转换（降 1 档 + 3 旬冷却）"，但 GDD v0.2 五节仍写"建议轻转换 ▲转路成本待拍板"——**两处不一致，需文策渊回写定稿**；另需定义转路 3 旬冷却期内熟练度加速是否失效（架构建议失效，防绕过成本）。
10. **履历归属与摄政资格、快照时点语义**（ARCH-002 新增）：① 摄政候选须曾任大夫档以上——玩家"择木而栖"换国后，原国任官履历是否计入新国摄政资格？（建议：履历按国隔离，跨季遗产加权另计。）② 席位影响 AI 决策权重，旬内换官时决策按"快照时点在任者生效"，此语义需策划确认符合叙事逻辑。
11. **API 限频与配额数值**（ARCH-003 新增；**ARCH-004 修订：定位转向"防作弊+防过载"，原保守建议值作废**）——新建议值见 ADR-005 哲学注记表：全 API 动作 ≤1200 次/时/Key（过载上限）、任务/会战日额度移除、会战冷却 ≥10s；**玩法节拍类约束（上书 1 次/旬/议题等）不变**。待 GDD-S7 v2 标定或推翻。
12. **托管等级与权限边界**（ARCH-003 新增）：① 摄政/席位**权限动作默认禁止 API 代驾**——需 GDD 确认是否永久红线；② 托管分级（全托管/半托管建议制/仅建议）属 GDD-S7 产品定义；③ API 代驾的策功/事功在摄政考评中是否与手操同权——建议 V1 同权但 agent_source 可区分，远期再议。
13. **代驾公开性与身份**（ARCH-003 新增）：① "客卿代笔"来源标记是否全国可见（架构建议：是——诚实原则，同时防冒充手操玩家）；② API 接入资格定位：是否 L3+/付费特权（影响配额成本模型与支柱三"参与阶梯"的定位，需 GDD 定）；③ 玩家声明 agent_id 的命名规范与公示。
14. **情报平等原则确认**（ARCH-003 新增）：API 信息=该账号 UI 可见信息超集、**无 API 专属情报玩法**——需 GDD-S7 确认不得存在"代驾专属情报"设计；会战窗口 API 竞态的"指令冷却"数值与"集结期 API 加速上限"需节奏测试标定（联动 S3 Q4）。
15. **托管两级化规格确认**（ARCH-004 新增，GDD-S7 v2 定稿项）：① 四级→两级（辅助/全权）的档位资格门槛（散阶档位+信用期）由设计侧定；② **高危确认动作集合的最终清单**（当前候选：兵符统领、议政案提交、摄政相关、身份性动作永不代行）——确认矩阵是数据驱动字段，清单定稿即配置；③ §2.7.4 实现项移除清单（每日额度/在朝时段/逐级降级/两项监控指标）需 GDD-S7 v2 白纸黑字确认取消，架构侧才执行移除；④ 防作弊五类（C1-C5）的处置参数（限速→冻结阈值、trust_credit 扣减/恢复规则）需与风控对齐标定。
16. **玩家主权原则的 GDD 定稿项**（ARCH-005 新增，GDD-S7 v2 定稿项）：① **撤销窗口与结算节奏的逐动作联动表**——"未结算"的边界逐类型定义（任务类=完成结算时点、会战类=冷却窗口 ≥10s、上书类=计票截止），需 GDD 逐项定稿；② 玩家在线判定标准与空闲超时（架构建议：有操作即活跃、空闲 15 分钟恢复自动化）；③ **OVERRIDE 免费原则确认**——覆盖免费、重提受玩法节拍约束，确认无"覆盖税"设计；④ **MANUAL_ONLY 最终清单**（与第 15 项高危清单合并定稿：身份性动作/兵符统领/摄政权限动作）；⑤ SUPERSEDED/REVOKED 痕迹在透明日志中的可见范围（架构建议：全国可见，透明原则）；⑥ 挂起期客卿建议推送的产品形态（待办笺 vs 建议卡，UX 定义）。
17. **离线授权（守舍）的 GDD 定稿项**（ARCH-006 新增，GDD-S7 v2 定稿项）：① **契约参数定义**：额度维度建议双轨（动作次数上限 + 资源/声望支出上限）、期限粒度建议以旬为单位；② **停机条件清单与事件映射**（候选：本国被宣战 / CRITICAL 短板 / 重大恩怨事件——哪些进默认停机、哪些可选订阅）；③ 守舍资格门槛（建议：全权资格 + 额外信用期，离线窗口无人工兜底故更严）；④ 离线额度与在线全权的额度差异（建议离线更紧）；⑤ 守舍报告的叙事化文案与呈现形态（"守舍回禀"，UI/文策认领）；⑥ 契约默认模板（一键"托付客卿"预设值）——影响首用体验。
18. **高位离席与代理的 GDD 定稿项**（ARCH-007 新增，设计侧《高位离席与代理》定稿项）：① 七折系数（0.7）与失期阶梯旬数的正式标定；② 告假最长期限与冷却阶梯（建议：告假 ≤2 旬自动转代摄、失期 2 旬收回）；③ **代理期政绩归属确认**（架构建议：策功/事功/摄政政绩全归代理者，权责一致）；④ 告假/失期对 AI 君主恩怨账本的影响（失期是否入 GRUDGE 软记忆，与人格卡 grudge_sensitivity 联动）；⑤ 回归交割的接任语义细节（代理期未决事项的交接清单规格）；⑥ 代摄动作与守舍契约互斥确认（架构建议：代摄属政治权限动作，不可入守舍契约——见 §2.9.5）。
19. **终局身份与认领的 GDD 定稿项**（ARCH-010 新增）：① 游客→正式账号认领的产品引导与文案（"旧游客数据全额继承"必须明示，防玩家误认数据清零）；② 观政模式（未登录只读入场）的产品边界——可看什么（国力仪表盘/诏令/史书）与不可交互清单（建议：一切写动作引导注册认领）；③ 透明日志与史书中玩家标识的展示口径（手机号/平台昵称的掩码规则，联动调整项 3 的脱敏规则）；④ BYO 客卿密钥仅存本地的用户沟通口径（"密钥不离开你的浏览器"作为安全卖点正向表述）。
