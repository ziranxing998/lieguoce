## 1. 推荐路线（一句话）

**单 VPS 轻栈：一个 Go 单体二进制 + 同机 PostgreSQL（+pgvector）+ 旬号 Cron 调度 + LLM 直连 SDK（配置切换供应商）+ 对象存储备份**——中性预估下全成本 **¥60~350/月**（30~300 CCU），且所有降级替换保持 ADR 决策逻辑与 schema 结构不变，V1 扩容时按触发器逐项升级回团队级方案。

## 2. 架构降级对照表

| 项 | 原方案（团队级） | 个人开发者方案 | 后果与代价 |
|---|---|---|---|
| 消息总线 | NATS JetStream | **PostgreSQL 队列表（SKIP LOCKED）+ LISTEN/NOTIFY** | ①Outbox 与业务同库同事务，一致性反而"免费"；②失去独立 broker 的重放/多消费者组——用"消费游标表"补偿；③300 CCU 量级吞吐毫无压力；④V1 扩容换 NATS 时 schema/事件语义零改动（信封已冻结） |
| 服务端 | 单仓三服务（game/ai-decision/gateway） | **单 Go 单体二进制**（模块边界=包边界，保持原有分层） | ①部署=一个 systemd 单元；②事务边界简化（跨域改同库事务）；③纪律要求：包间依赖单向（`internal/` 分层 lint 强制），防单体腐化——这是扩容时能拆回去的前提 |
| 旬/事件调度 | B1 旬度调度器服务 | **Cron/内嵌 ticker**（旬号时钟服务降级为单表 + 每分钟检查） | 旬作业编排逻辑不变（快照→LLM→校验→下发），只是进程内调用 |
| LLM 网关（B3） | 自建多供应商网关 + LiteLLM 起步 | **直连云厂商 SDK + 极简中间件（~300 行）**：超时/重试(≤2)/预算熔断/降级模板 | ①多供应商抽象降级为**配置切换**（改 env 即换模型）；②失去实时 token 计量大盘——用"每日余额检查 + 熔断计数器"替代；③人格卡缓存改用厂商原生 prompt cache（直连即原生支持） |
| 玩家 API 网关（A7） | 独立网关子域 | **V1 前不建**（与既有决策一致：MVP-0 仅 schema 预埋 agent_source） | V1 若 CCU 低，用单体模块 + 反向代理（Caddy）实现，不新起服务 |
| 向量检索 | pgvector | **保留 pgvector**（自装 PG 或托管 PG 均自带）；最坏降级为结构化检索 | 硬记忆本就确定性注入（不依赖检索），软记忆降级只损失叙事质感不损失人设承诺 |
| 决策状态机/冷却注册表/归因账本 | PostgreSQL | **不变**（本就 PG） | 零改动 |
| 透明日志 | B7 独立服务 | 同库审计表 + 上线拉取接口 | 存储/查询语义不变 |
| GM 工具 | E1.7 后台 | **SQL 脚本集 + 少量 CLI 命令**（开发者本人就是 GM） | 调参审计用 git 管理配置文件替代 |
| 监控 | E7 大盘 | UptimeRobot/healthchecks.io + 日志文件 + 旬作业心跳 | 见 §6 |

### 两条路线对比与推荐

| 维度 | A 全托管（Supabase/Neon + Serverless） | B 单 VPS 轻栈（推荐） |
|---|---|---|
| 月费（300 CCU） | ~¥300-400（Pro 档 + 函数调用 + 出口流量） | ~¥280（VPS 8C16G + 备份） |
| 运维负担 | 最低（备份/补丁托管） | 中（一次 Ansible 脚本 + 例行巡检，见 §6 降到每周 1h 内） |
| 长任务适配 | 差：旬决策批处理是分钟级长任务，Serverless 冷启动/超时别扭，需拆分异步状态机 | 好：常驻进程天然适配 Cron + 批处理 + 心跳 |
| LLM 直连 | Serverless 出口 IP 不固定，部分供应商需配代理 | 直连无障碍 |
| 调试/数据自主 | 平台黑盒居多 | psql 直查，个人开发者调试效率高 |
| 锁定风险 | 中 | 无 |

**推荐 B（单 VPS）**：本项目负载形态（旬制批处理 + 常驻会话 + 低并发）与常驻进程天然契合；全托管方案作为"完全不想碰服务器"时的备选，两者共享同一份单体代码（连的是托管 PG 还是本机 PG 只是连接串差异）。

## 3. LLM 成本引擎（核心章节）

### 3.1 模型分级策略

| 场景 | 模型档 | 理由 |
|---|---|---|
| 旬决策（国策诏/任务潮权衡/复盘语录） | **小模型** | 结构化输出为主，人格由人格卡+少样本锚定；一旬一次，质量问题有降级模板兜底 |
| 事件决策（宣战/天灾/叛逃） | 小模型（重大事件可选强模型，白名单 ≤3 类） | 频次低；宣战檄文等高戏剧性场景才值得强模型 |
| 自由对话（L3 朝堂） | **中模型 + 硬预算熔断** | 唯一的成本大头（见 3.4）；人格一致性与流式体验优先 |
| 摘要/守舍报告/史书素材 | 小模型 + 批处理 | 离线任务 |
| 廷议/摄政仲裁理由 | 强模型 | 政治戏剧核心场景，频次极低 |

### 3.2 上下文预算硬上限（单次调用）

| 场景 | 输入 | 输出 | 缓存策略 |
|---|---|---|---|
| 旬决策 | 12K（人格卡 3K + 快照/记忆 9K） | 3K | 人格卡走 prompt cache（命中价 ~1/5） |
| 事件决策 | 8K | 2K | 同上 |
| 自由对话 | 5K（含会话摘要截断：会话历史 >3K 时只保留摘要+近 3 轮） | 1.5K | 会话摘要旬度压缩 |
| 摘要/报告 | 10K | 2K | — |

**硬上限纪律**：prompt 组装超预算即截断（先砍软记忆、再砍事件流细节、人格卡与硬记忆永不砍）——预算熔断从入口就生效，不靠事后止损。

### 3.3 估算公式

```
月 LLM 成本 = 旬决策 + 事件决策 + 自由对话 + 摘要
  旬决策  = N_君主 × 旬/月 × 单次成本(in_tok×p_in + out_tok×p_out) × 重试系数(1.3)
  事件决策 = 事件次数/月 × 单次成本
  自由对话 = L3人数 × 3次/日 × 30 × 单次成本        ← 成本大头
  摘要     ≈ N_君主 × 旬/月 × 单次成本（量级可忽略）

  其中：旬/月 = 30/旬周期天数（3 天旬 = 10，7 天旬 ≈ 4.3）
  L3人数 = CCU × 5%（配额 3 次/日已含限频）
```

**旬周期 3 天→7 天的影响：LLM 成本中旬决策与摘要部分 ÷2.3，自由对话不变**（对话按日不按旬）。按 §3.4 数字，7 天旬使中性档总 LLM 成本降 ~35-40%，且给批处理窗口与个人运维留更大余量——**架构侧支持 7 天旬，数值/节奏取舍归设计侧（GDD-S10）**。

### 3.4 三档 CCU 估算（¥/月；单价假设：小模型 in ¥1/M·out ¥4/M·缓存 ¥0.2/M；中模型 in ¥4/M·out ¥16/M；强模型 in ¥18/M·out ¥72/M；3 君主；旬=3 天）

| CCU | 乐观（全小模型+缓存全命中） | 中性（分级模型+部分缓存+重试1.3） | 悲观（全强模型+无缓存+重试1.5） |
|---|---|---|---|
| **30** | ¥2（7天旬 ¥1） | **¥7（7天旬 ¥4）** | ¥50（7天旬 ¥22） |
| **100** | ¥5（7天旬 ¥3） | **¥23（7天旬 ¥9）** | ¥113（7天旬 ¥48） |
| **300** | ¥13（7天旬 ¥6） | **¥70（7天旬 ¥26）** | ¥291（7天旬 ¥127） |

**解读（比数字更重要的结论）**：
1. **旬决策在三个数量级之下**（中性 300 CCU 仅 ¥7/月）——"AI 君主"这个核心卖点的 LLM 成本几乎免费，真正的成本变量只有一个：**自由对话人数 × 模型档位**。
2. **悲观档 ≈ 全强模型且无人管**——防它的手段不是省钱而是既有机制：D1-D3 熔断（ARCH-003/ADR-005）+ **¥100/日/服封顶线（ARCH-009 拍板，见 §3.5）** + 旬决策强制小模型白名单。
3. 个人开发者**默认姿态**：旬决策/事件/摘要全小模型起步，只有 L3 对话与廷议开中模型；强模型仅宣战檄文等 ≤3 类白名单场景。

### 3.5 ¥100/日封顶线落地（ARCH-009 拍板）

- **定位**：保险丝（异常兜底），不是预算——中性档月 LLM 成本 ¥70-150，封顶线月最坏 ¥3000 只在滥用/事故时触及。
- **计量范围（关键 carve-out）**：封顶线只计**可限流成本**=自由对话 + 事件决策（强模型部分）+ 客卿相关调用。**旬决策/摘要（小模型）走独立小池预扣（~¥5/日上限）不参与熔断**——否则一次异常日会切断"每旬必有国策诏"的核心承诺（先秦文策承诺优先于省钱）。
- **熔断触发后的降级链顺序**（对齐 ARCH-003 D1-D3）：
  1. **D1 限长**（日累计 ≥¥80）：长文异步关闭，仅短句流式；
  2. **D2 限频**（≥¥90）：自由对话配额减半；
  3. **D3 模板化**（≥¥100）：自由对话关闭、事件决策强模型切小模型、新会话拒入——全部人格化包装（"倦勤"话术库）；
  4. **恢复**：次日 0 点计量重置；D3 恢复须整旬缓冲（防预算贴线震荡，ARCH-003 既定）。
- **告警**：日累计 ≥¥50 即邮件通知开发者（保险丝触发前人工可介入）；封顶触发本身入透明日志。

## 7. 架构不变量与 ADR 补充条款

### 7.1 不变量（规模无关，任何形态下不妥协）

1. **schema v1 冻结结构**（schema-freeze-preview.md）：信封/trace/枚举/事件类型——扩容换 broker、换部署形态均零改动；
2. 旬号确定性版本轴、快照冻结语义、决策状态机（PENDING→VALIDATED→PUBLISHED 与玩家域 SUBMITTED→VALIDATED→SETTLED）；
3. 事件溯源 + Outbox 语义（solo 下 Outbox 与业务同事务，反而更简单）；
4. 硬记忆确定性注入、归因链、agent_source 审计、玩家主权三语义（覆盖/抢断/ MANUAL_ONLY）；
5. 降级链存在性（"每旬必有国策诏"承诺）——solo 形态下它同时是无人值守的保险。

### 7.2 ADR 补充条款清单（各补一行"solo 形态"，原决策逻辑保留）

| ADR | solo 补充条款 |
|---|---|
| ADR-001（LLM 提供方） | **solo**：自建网关 → 单文件 LLM client 模块（重试/熔断/降级模板 ~300 行）；多供应商=配置切换；Batch API 可选；模型分级与预算封顶为强制项（§3） |
| ADR-002（通信边界） | **solo**：NATS JetStream → PostgreSQL 队列表（SKIP LOCKED）+ LISTEN/NOTIFY；Outbox 与业务同事务；消费游标表替代消费者组；决策状态机与版本化下发不变 |
| ADR-003（记忆存储） | **solo**：pgvector 保留（自装/托管 PG 均支持）；无向量条件时软记忆降级为结构化检索（硬记忆不受影响） |
| ADR-004（引擎选型） | **solo**：三服务 → 单 Go 单体二进制（`internal/` 包分层 + 依赖方向 lint 强制，保拆分能力）；客户端引擎倾向不变 |
| ADR-005（玩家 API） | **solo**：MVP-0 仅 schema 预埋（既定）；V1 网关用单体模块 + Caddy 反代实现，不新起服务；守舍契约/三态判定/五类作弊检测语义全部保留（本来就是服务端逻辑，无规模依赖） |

### 7.3 扩容触发器（何时升级回团队级方案）

| 触发条件 | 动作 |
|---|---|
| CCU 稳定 >500 或单 VPS CPU 持续 >70% | 单体拆分：先拆 ai-decision（批处理隔离） |
| PG 队列表积压/延迟超 SLA | 引入 NATS JetStream（信封零改动） |
| LLM 月费连续 2 旬 > ¥500 | 自建网关（计量粒度回诉求）+ 重评模型分级 |
| 玩家 API 内测人数 >200 | A7 独立部署 |
| 多服开服 | B 层跨服共享 + 分服部署（原架构基线形态） |

## 8. 与设计侧协同项（GDD-S10 对齐）

1. 三档成本已按 30/100/300 CCU 给出（§5）；**建议 MVP-0 以 30 CCU 档为预算锚**（¥60/月中性），100/300 档作为内测放量时的阶梯验证；
2. 旬周期 3→7 天：LLM 成本降 ~35-40%（§3.3），且运维余量更大——架构无异议，节奏取舍归设计侧；
3. 自由对话配额（L3 3 次/日）是成本第一变量：若 MVP-0 砍 L3 对话（S1 §7.3 的齐国试点推迟），中性档 LLM 成本再降 ~80%（30 CCU 档 → ¥1.5/月）——**这是个人开发者最值得做的一刀**，交设计侧裁决；
4. 强模型白名单场景清单（建议：宣战檄文/廷议仲裁/赛季史书，≤3 类）需设计侧确认。

## 9. 容量路线图（ARCH-009 新增：大容量方向）

> 用户拍板：参考率土之滨的大服务器框架（单服上千人级），但玩法是决策+执行两路（旬制决策+任务+节点会战），非实时格子占地、非卡牌数值——目标是**大幅增加服务器玩家容量**。设计侧并行产出 S11《大容量服务器与玩家分层》（核心层/乡野层/客卿长尾），本节按**单服目标 1000-3000 人、核心:长尾 = 2:8** 的负载模型先行论证。

### 9.1 为什么本作比率土更容量友好（技术论证）

| 维度 | 率土之滨类（实时格子占地） | 本作（决策+执行两路） |
|---|---|---|
| 写负载节奏 | 每秒级：行军 tick、占地攻防、格子状态高频变更 | 每人每小时几次结构化动作（接任务/提交/上书）——人类手速，不是机器人频率 |
| 战斗计算 | 高频帧级/格级战斗结算，位置同步 | 节点推进会战 36-48h 窗口，推进度按任务贡献结算（无帧同步、无物理） |
| 决策负载 | 常驻指令即时响应 | **旬制批处理**：AI 决策每旬一次异步批跑，根本不在玩家同步路径上 |
| 写的时空分布 | 集中在国土边界接触带，热点格子写冲突严重 | 玩家动作均匀散布全天与全部内容类型；旬结算集中写由队列表分批吸收 |

结论：本作的负载形态是"**低频人类动作 + 周期性批处理**"，容量瓶颈比格子国战晚一个数量级出现。

### 9.2 负载模型与单机天花板

**负载模型（2:8）**：DAU = D；核心层 0.2D（峰值在线 25%、峰值 ~8 req/min）；乡野/客卿长尾 0.8D（峰值在线 5%、~0.5 req/min）。**峰值并发在线 ≈ 0.09D，峰值请求 ≈ 100 rps @ D=3000**（(600×8+2400×0.5)/60）。

| 单机档 | 估算 DAU（舒适上限） | 峰值并发在线 | 峰值 rps | 月成本 |
|---|---|---|---|---|
| 4C8G | ≤1,000 | ~90 | ~30 | ≈¥100 |
| 8C16G | **2,000-3,000** | 180-270 | 70-100 | ≈¥250 |

**关键瓶颈标注**：
1. **DB 写入（旬结算批处理）**——最需要纪律的点：旬结算/归因聚合必须走队列表**分批消费**（每批 ≤500），禁止一次性全量事务；20 行代码换 10 倍峰值容量；
2. **会战窗口推进度提交**——唯一的高频写窗口：乐观并发版本 + 队列缓冲已就位（schema 冻结含此语义）；
3. **LLM 编排吞吐——不是容量瓶颈**：异步批处理，只影响决策延迟不影响在线人数；
4. 连接数：Go pgx 连接池 + HTTP keep-alive，单机数千连接无压力；无 WebSocket 强需求（长文"诏书送达"用拉取）。

### 9.3 扩容路线（无微服务，每档零 schema 变更）

| 档 | 形态 | 估算 DAU | 月成本增量 | 改动内容 |
|---|---|---|---|---|
| L0 | 单机 4C8G | ≤1,000 | 基线 ¥100 | — |
| L1 | 单机 8C16G | 1,000-2,000 | +¥150 | 升配而已 |
| L2 | **双机**：应用机 + DB 机（读写分离 + 按旬/按国表分区） | 2,000-4,000 | +¥250（总 ≈¥500） | 连接串 + 分区表 DDL（分区键 `nation_id`/旬号已在冻结 schema） |
| L3 | **按国分片的多进程单体**（同一二进制多实例，分片键 nation_id，每片独立 DB） | 4,000-10,000+ | +¥300-700（总 ≈¥800-1,200） | 部署编排（docker compose 多份）+ 跨国事件路由（总线 topic 已按国分区） |

**单服 1000-3000 人可行性结论：可行（附三个条件）**——①2:8 负载模型成立（乡野层确实是低频低带宽，待 S11 确认玩法支撑）；②旬结算/会战窗口走队列分批（工程纪律，非架构变更）；③DAU >2000 时升级 L2 双机（+¥250/月，半小时操作）。schema v1 冻结已含分片键（nation_id）、玩家分层字段位、统计聚合接口位——**大服-ready 从第一天在 schema 层做进，扩容工程绝不提前做**（YAGNI 纪律）。

### 9.4 决策输入分层统计聚合（对 LLM 成本的影响评估）

设计侧需求：AI 君主决策输入从个体行为改为分层统计聚合（乡野层只进统计）。**架构评估结论：token 预算不变，成本结论不变**：
- S1 M2 快照**本来就是聚合统计**（议题去重计数/任务类型完成率/分群摘要），分层改造改变的是**聚合的分组方式**（按核心/乡野分桶），不改变**聚合结果的 token 量级**——聚合表控制在 **≤2K token/君主/旬**（固定，与人口规模无关）；
- 聚合后单旬决策 token 预算：人格卡 3K（缓存）+ 国力五维与环比 1.5K + **分层行为聚合 ≤2K** + 外交事件流 1K + 硬记忆 1-2K + 软记忆 top-K 1.5K ≈ **输入 10-11K / 输出 3K**——与 §3.2 既有预算一致；
- **关键性质：旬决策成本是 O(君主数) 而非 O(玩家数)**——1000 人服与 100 人服的旬决策成本相同（中性 ≈7 君主 × 4.3 旬 × ¥0.02 ≈ **¥0.6/月**）。人口增长只影响 ①聚合 SQL 计算（旬批处理内，免费）②透明日志存储（线性、廉价）。**因此 1000+ 人服的旬决策成本证明可控，容量天花板由基础设施决定，与 AI 成本彻底解耦。**
- 防操纵继承：单玩家对聚合输入的影响上限 ≤5%（S1 §3.2 既有护栏），分层后按层分别生效。

### 9.5 需策划侧知悉项（S11 对齐）

1. **乡野层埋点与聚合粒度建议**：议题级/任务类型级/阵营级计数（单玩家旬内去重），聚合快照硬上限 ≤2K token——超出即降分组粒度，不做玩家级明细注入；
2. **分层判据**（核心/乡野的划分标准：活跃度阈值还是官职档位）由设计侧定——架构按 2:8 负载模型预留分层字段，判据是纯配置；
3. **容量目标建议值**：内测锚 2000 DAU（L1→L2 拐点验证），设计上限 3000；不要按"注册用户"规划容量（按 DAU 与 2:8 模型）；
4. 会战窗口节点提交频控与批量结算参数（推进度提交建议冷却 ≥10s，与客卿会战冷却同源）；
5. 核心层"个体代表行为"进 prompt 的取样规则（若设计侧希望君主"记得"个别核心玩家）：建议白名单式（摄政/高位者动作走既有恩怨账本通道），不走统计快照——防注入与防操纵边界保持清晰。

## 10. 单文件交付约束（ARCH-010 新增：发布平台形态）

> **重要发现**：发布平台只服务**入口 HTML 单文件**——入口引用的所有外链文件（JS/CSS/图片/字体）一律 403。试玩版（liguoce-trial）已改为单文件交付：Auth/云服务 SDK 内嵌 + 图片 base64 内联。本节为所有经发布平台分发的 Web 入口（试玩版、推广页、MVP-0 若走 Web 客户端）的强制约束；**正式游戏服务端（单 VPS 轻栈，§1）与未来原生客户端不受此约束**。

### 10.1 交付形态与架构含义

- 单 HTML 文件 = 结构 + 样式 + 脚本（SDK 内嵌）+ 图片（base64 data URI）。**无 CDN 分层、无懒加载分块、无 Service Worker 预缓存——首屏即全量下载**。
- 推论①：**SDK 版本升级 = 重发整个文件**，无增量更新——SDK 升级随版本发布节奏走，不追热修；升级前本地全功能回归。
- 推论②：**浏览器 localStorage 成为信任根**——Auth 会话与客卿 BYO 密钥（ADR-005/006：密钥仅存玩家浏览器，服务端不经手）都落本地存储。单文件形态下没有 httpOnly cookie 会话的服务端承载面，此为接受的权衡（试玩/推广场景风险面可接受；含真实支付的正式客户端另议，须重新评估）。
- 推论③：禁外链意味着字体也须子集化内嵌（如需中文字体，只嵌用到的字形子集，不做全量字体文件）。
- 推论④：单文件天然规避多资源缓存一致性问题；分发缓存由发布平台侧处理，本地无 CDN 配置负担。

### 10.2 规模预算（强制）

**HTML 总量 ≤1.5MB**（监控 gzip 后传输体积，源文件以此为上限锚）。分配建议：

| 项 | 预算 | 说明 |
|---|---|---|
| 代码（含内嵌 SDK） | ≤500KB | Auth SDK + 云服务 SDK + 游戏逻辑，minify 后 |
| 图片（base64 后） | ≤900KB | base64 有 1.33x 膨胀，对应源图片预算 ≈675KB |
| HTML/样式/余量 | ≤100KB | 结构 + CSS + 版本信息 |

**超 1.5MB 即 CI 失败**——构建脚本输出每图与总体积报告，预算纪律靠自动化不靠自觉。

### 10.3 图片压缩管线（sharp）

```
sharp(input)
  .resize({ width: 768, withoutEnlargement: true })   // 展示宽度 2x 余量，768px 封顶；小图按原尺寸不放大
  .webp({ quality: 72, effort: 5 })                    // WebP 替代 JPEG/PNG，同观感省 25-35%
  .toBuffer()
```

- **单图目标**：全图类 ≤60-80KB，头像/图标类 ≤15KB；
- **超预算降级顺序**：先降 quality（72→60→50），再降宽度（768→512→384）——保观感优先于保分辨率；
- **禁 PNG 照片类**：截图/插画一律 WebP（JPEG 兜底兼容性留待验证后放开）；线稿/图标类可 SVG 内联（无栅格化成本）；
- 管线参数若实测观感不达标（quality 60 以下出现色带），优先减图量/减尺寸而非回退 PNG。

### 10.4 与既有方案的边界

本约束**不改变** §1-§9 的任何结论：游戏服务端仍在单 VPS 轻栈，前端若日后迁移独立托管（自有域名 + CDN）即解除本约束；它只约束"经由发布平台分发的 Web 入口"这一分发通道的资产形态。试玩版已按本约束完成改造（SDK 内嵌 + 图片 base64），作为本节预算与管线的首个实测样本。
