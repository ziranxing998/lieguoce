## Spike ① 旬决策全链路（快照→Batch→校验→状态机→降级链）

| 项 | 内容 |
|---|---|
| **目标** | 端到端验证旬度决策流水线（架构基线 §2.2 主路径）与降级链，收口风险 #1（旬决策失败断节奏）与风险 #2（结构化输出不可靠），为 E2 Epic 提供骨架代码与可靠性数据 |
| **范围** | ① 快照冻结器最小实现（输入可 mock：国力三维/玩家行为/事件流，引力层置空）；② LLM 网关 Batch API 调用与轮询；③ 国策诏 JSON Schema（对齐 S1 §4.3 结构）+ 校验 + ≤2 次修复重试；④ 决策状态机 PENDING→VALIDATED→PUBLISHED 与版本化下发（旬号+序号）；⑤ **降级链演练**：注入主模型故障→备用模型→冻结上旬+GM 注入→模板诏令（对齐 S1 §3.3），四条路径全部可触发、有日志与告警 |
| **DoD** | 1. 3 国（秦/齐/楚占位人格卡）批量旬决策全链在 **60 分钟窗口内**完成；2. 降级链四路径演练通过，每条路径的玩家可见产物（诏令/语录）符合"每旬必有国策诏"承诺；3. 状态机非法迁移（如 VALIDATED→PENDING）被拒绝且有审计；4. 同旬号重复下发结果幂等一致；5. 快照冻结语义测试：冻结后上游输入变化不影响已生成快照；6. 单次旬决策 token 计量准确（与供应商账单偏差 ≤5%），修复重试成本系数实测（校验架构预算模型的 1.3-1.5 倍假设） |
| **预计人日** | 8-10 人日（1 人） |
| **依赖** | 无前置 spike，可即刻开工。需要：LLM 供应商账号（至少 2 家，含 Batch API 配额）、JSON Schema 约束解码能力验证（各家支持度不一，是网关抽象层的输入） |
| **风险** | Batch API 处理时长不可控（供应商 SLA 波动）→ 设计超时+轮询+窗口余量，实测数据回填旬窗口 30-60 分钟的假设；快照冻结若依赖真实上游服务则范围膨胀 → 本 spike 一律 mock 输入，只验冻结语义 |

## Spike ② 人格卡 + 硬记忆一致性测试集初版

| 项 | 内容 |
|---|---|
| **目标** | 建立"人格漂移检测 + 硬记忆注入验证 + 文风过滤"的自动化回归套件初版（对齐 S1 §3.1 回归测试、§8.2 护栏指标、G4 行为连续性），验证支柱一"君主是活的"的技术可行性 |
| **范围** | ① 秦/齐 2 张完整人格卡（按 S1 §4.1 字段表）+ 楚原型卡占位；② 20 条固定历史输入重放集（对齐 S1 §3.1 季度回归规格）与"决策倾向偏差 ≤15%"的量化方法；③ 硬记忆确定性注入验证：mock 恩怨账本（通缉名单/BETRAYAL 条目），断言决策与语录 100% 体现；④ 文风过滤器初版：禁现代词汇表（50 词测试集）+ 先秦语感校验；⑤ 语录依据字段强制校验（S1 M7：每条语录 ≥1 条 judgment_basis 且与事实一致） |
| **DoD** | 1. **盲测正确率 ≥60%**：去标识诏令 20 条，人工按评估 rubric 猜国（S1 G1 指标）；2. 硬记忆注入率 100%：含通缉条目的 prompt 产出的诏令/语录 100% 相关体现（自动断言+人工抽检各 10 条）；3. 文风过滤器：50 词注入测试拦截率 100%、误杀率 <5%；4. 回归测试一键重跑，输出偏差报告（阈值 15% 对齐 S1 §8.2）；5. 评估 rubric 文档化（供后续季度回归复用） |
| **预计人日** | 6-8 人日（1 人，评估盲测可借调文策 0.5 人日） |
| **依赖** | 部分（后半段）依赖 Spike ① 的 prompt 组装与校验骨架；恩怨账本用 mock 不依赖 M8 实装 |
| **风险** | "决策倾向偏差"量化无先例 → 本 spike 的首要产出之一就是量化方法定稿（候选：人格五维在输出中的体现度评分/目标类型分布偏移）；盲测主观性 → 用 rubric + 双人独立评分缓解 |

## Spike ③ 策功归因链事件最小验证

| 项 | 内容 |
|---|---|
| **目标** | 验证归因链 trace 字段全链路透传与策功/事功双轨账本"同源不出叉"（S2 §4.4/§4.5），**冻结事件 schema v1**（架构基线 ADR-002 后果⑤/§2.6.1——现在不做以后补不回的技术债） |
| **范围** | ① 事件 schema v1 冻结：`trace = {proposal_id, decree_id, task_id, 旬号, 赛季号}` + `origin` 标记（AI_DOMESTIC/DECAY/EVENT/OTHER_TASK）+ **`agent_source` 必填枚举（HUMAN_UI / PLAYER_API）与 `agent_id` 可空字段（ADR-005，ARCH-003 修订：schema v1 冻结必须包含，冻结动作不得先于本字段定稿）** + **`origin_action_id`/`superseded_by` 字段与 REVOKE/OVERRIDE 审计事件类型（ARCH-005：玩家主权覆盖语义）** + extensions 预留；② NATS JetStream 最小拓扑（按国家分区键有序）+ Outbox 模式（DB 事务与发布一致性）；③ 端到端事件链：ProposalSubmitted→ProposalAdopted→DecreePublished→TaskGenerated→TaskCompleted→AttributionWriteback；④ 双轨账本写入（同一 delta_event 同时喂策功链与事功链）；⑤ 归因查询视图（按 proposal_id 聚合净增量）；⑥ 归因窗口（2 旬）与 source 隔离规则（S2 §4.5 六条）实现 |
| **DoD** | 1. 事件 schema v1 冻结文档 + JSON Schema 校验器：**缺 trace 必填字段的事件被拒绝发布**（发布端强校验）；2. 全链 ID 透传无断点（端到端自动断言）；3. 双轨同源测试：同一增量事件产生的策功流水与事功流水数值一致；4. S2 §4.5 分摊规则六条全部有测试覆盖（含窗口边界：超窗收益转 OTHER_TASK 不计策功；ref_goal_id 唯一性约束）；5. Outbox 一致性测试：DB 提交后消息至少一次送达，消费幂等（重复投递不重复记账）；6. 跨旬窗口测试用旬号时钟 mock 加速模拟 |
| **预计人日** | 6-8 人日（1 人） |
| **依赖** | 无硬依赖，可即刻开工；数据结构对齐 S2 §4.4/§4.5（已定稿 ✔） |
| **风险** | schema 冻结过早漏字段 → 以 `extensions` 自由字段缓冲 + 冻结只覆盖必填核心；跨旬归因窗口测试周期长 → 旬号时钟抽象为可 mock 组件 |

## Spike ④ 玩家 API 最小链路验证（客卿代驾，ARCH-003 新增）

| 项 | 内容 |
|---|---|
| **目标** | 验证 ADR-005 玩家拉取-提交模式端到端可行性：上下文包渲染 → 玩家 mock Agent → 结构化动作提交 → 白名单校验 → `agent_source` 标记入账 → 审计闭环，为 V1 玩家 API 全量提供安全骨架与参数依据 |
| **范围** | ① 上下文包渲染器（信息平等原则：包字段 = UI 可见信息超集的机器可读渲染）；② 动作白名单 schema（MVP 最小集：上书建议卡提交 + 任务领取两类）+ **数据驱动确认矩阵扩展三值 authority: AUTO_OK / CONFIRM / MANUAL_ONLY（ARCH-004/005，客户端不可改）+ 二元托管状态（ASSIST/AUTONOMOUS，ARCH-004）**；③ 四层过载保护令牌桶（Key/账号/风控簇/路由，**宽松默认值 ≤1200 次/时/Key——定位为过载保护而非行为矫正，ARCH-004**）；④ 幂等键 + 单调动作序号 + 乐观并发版本；⑤ 叙事字段净化路径验证（标记隔离，断言不进君主决策流）；⑥ agent_source 事件流转与透明日志归档；⑦ **五类作弊检测断言集（C1 越权/C2 知识边界/C3 身份伪造/C4 归因污染/C5 资源竞态——见基线 §2.7.2，各 ≥1 条自动化测试）**；⑧ **玩家主权元动作（ARCH-005）：ACTION_REVOKE / ACTION_OVERRIDE + 玩家域动作状态机 SUBMITTED→VALIDATED→SETTLED（REVOKED/SUPERSEDED 终态）+ 会话互斥挂起（SUSPENDED）**；⑨ **离线授权守舍（ARCH-006）：授权契约对象（服务端构造/TTL 期限）+ 三段执行判定（在线手动/在线全权/离线授权）+ 额度预扣-对账 + 停机事件订阅（≤60s p99）+ 守舍报告 digest** |
| **DoD** | 1. **信息平等测试**：包内任意字段均可在该账号 UI 某处查到（自动比对断言，新增字段无 UI 对应即 CI 失败）；2. 动作白名单：schema 外动作 100% 拒绝（模糊测试 ≥200 变体）；3. 注入测试集：叙事字段嵌入指令（≥30 样本）0 例进入君主决策流；4. 幂等/竞态：同 request_id 去重、序号乱序拒绝、并发版本冲突拒绝均有测试；5. 四层过载保护在**宽松默认值**下独立生效且取最严（断言的是保护上限生效，非行为矫正——1200 次/时内正常使用零打扰）；6. HUMAN_UI 与 PLAYER_API 双路径产生的事件 agent_source 正确落透明日志；7. **五类作弊检测断言全绿**（ARCH-004 新增）：越权动作/确认矩阵绕过被拒、包外字段探测被画像上报、agent_source 伪造被拒、双 ID 不一致告警、会战并发冲突拒绝；8. 冻结→回退手动降级链演练通过（心跳超时 → 自动化冻结 → 待办笺承接 → 手动接管）；9. **玩家主权断言全绿（ARCH-005 新增）**：manual_only 动作 API 提交被拒且错误码区分、SUBMITTED 态 REVOKE 生效且重复 REVOKE 幂等、VALIDATED 态 OVERRIDE 产生 SUPERSEDED 痕迹+归因清零+新动作重提、**在线抢断互斥**（玩家会话活跃时自动化动作在结算前检查点被挂起、空闲超时自动恢复）、REVOKE/OVERRIDE 审计事件含 superseded_by 落透明日志；10. **守舍契约断言全绿（ARCH-006 新增）**：契约外动作离线执行被拒（越界拒绝）、额度预扣→超限熔断→转待办→上线交接全链（且超限**不扣** trust_credit）、契约过期/TTL 自动失效、三态判定优先级（在线手动挂起 > 在线全权 > 离线受契约）、停机事件端到端时延 ≤60s（mock 宣战事件注入）、守舍报告 digest 与透明日志动作流水一致性核对 |
| **预计人日** | 8-10 人日（1 人；ARCH-004/005 断言扩充 +2，ARCH-006 守舍契约 +1，原 5-7 基数上调） |
| **依赖** | E1.5（事件 schema v1 冻结，含 agent_source——Spike ③ 产出）、E6.1（鉴权框架）；GDD-S7 v2（托管两级/确认矩阵高危清单/守舍契约参数回写）；不阻塞 E2/E3 主线 |
| **风险** | 信息平等自动比对需 UI 数据点清单（依赖客户端侧配合，可先用服务端"UI 数据出参"清单近似）；动作白名单 MVP 最小集之外的形态待 GDD-S7 定稿后扩展 |

## MVP 技术栈落地建议（倾向性意见，待正式 ADR-004）

> 以下为按 ADR-001~003 与三份系统 GDD 推演的**首版倾向**，标"倾向"处待团队技能盘点与正式 ADR 定稿。

| 层 | 倾向选择 | 理由 | 备选与触发条件 |
|---|---|---|---|
| 服务端语言/框架 | **倾向 Go 1.22+**（单仓多服务：game / ai-decision / gateway 三部署单元） | 事件溯源+消息消费+批处理调度是 Go 强项；单二进制部署降运维；国内 MMO 服务端人才可得；与 Spike ①③ 代码直接演进 | C#/.NET 若团队池明显偏 C#（S3 状态机/会战窗口的实时性两者都够） |
| 消息总线 | **NATS JetStream**（ADR-002 已定方向） | 轻量、按 subject 分区有序、Outbox 友好；MVP 规模（3 国、万级 DAU）远够 | Kafka 触发条件：V1 跨服会盟的吞吐/生态需求出现时 |
| 数据层 | **PostgreSQL 16 + pgvector**（ADR-003）；Redis 7（会话/限频/缓存） | 归因账本/恩怨账本/透明日志全是关系型强约束场景；pgvector 免独立向量库运维；`UNIQUE` 约束天然兜底席位锁（基线 §2.6.2） | 无——MVP 不考虑替代 |
| LLM 网关 | **倾向自研轻量 Go 网关**；评估 **LiteLLM proxy** 作为 Sprint 1 快速起步 | 计量熔断/降级分级/人格卡缓存是本项目定制逻辑，长期必须自研；但 Sprint 1 用现成 proxy 先跑通 Spike ①，避免过早基建 | 若 LiteLLM 覆盖 Batch+计量则延长借用期，自研推迟到 Sprint 4 |
| 客户端引擎 | **倾向 Unity（2022 LTS 或 6.x LTS）+ UI Toolkit** | 竹简/帛书文档型 UI 是本项目主要 UI 形态，UI Toolkit 数据绑定契合；MMO 人才池 | UE5 仅当画面目标显著上调时重评（成本高） |
| 部署 | MVP：单云 + Docker Compose（3 服务 + PG + Redis + NATS）；V1 迁 K8s | 旬制批处理+分钟级事件决策的负载曲线平缓，MVP 不需要编排复杂度 | — |

**技术栈决策记录提示**：Sprint 1 结束时以 Spike ① 的网关实测数据 + 团队技能盘点收口 ADR-004，替换本节"倾向性"字样。
