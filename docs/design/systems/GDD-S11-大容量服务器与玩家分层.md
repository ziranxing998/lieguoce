## 1. 系统概述

**系统命名**：**「万民册」**（大容量服务器与玩家分层）。

**定位一句话**：*让一个单人可运维的服务器，装下率土之滨量级的人口——靠的不是更强的机器，而是"分层"与"聚合"这两台先秦滤镜。*

**要解决的问题（为什么需要本系统）**：v0.9 定位拍板后，本作参照系从"小服深度社群"升级为"率土式大服"——单服注册目标 1 万+、注册峰值远超 MVP-0 的 30-100 CCU 假设。直接放大会撞上两堵墙：① **AI 上下文爆炸**——君主四层输入中的"玩家行为聚合"层若逐条纳个体数据，人口 ×10 则 token 成本 ×10，铁律二直接破产；② **玩法稀释**——朝堂席位与摄政位是稀缺资源，万人在服时 99% 的玩家将长期与核心玩法无缘，流失即崩。本系统的答案是**金字塔分层**：核心层（散阶+席位+摄政，吃 AI 深度）与乡野层（民间玩法，吃规则引擎），配以**分层统计聚合**让 AI 成本与人口**亚线性**增长。

**与参照系的关系（承接 GDD-0 §一参考系声明）**：借鉴率土之滨的是**运营骨架**——大服容量、赛季制、列国对抗、同盟政治、沙盒涌现；拒绝的是**表达层**——格子占地（本作版图改变走会战节点推进制与政治结果，地图是水墨画布不是格子棋盘）、卡牌收集（玩家是"士"本人，无抽卡无武将卡池）、数值堆砌（成长走方略采纳-执行-归因闭环，数值只是"物理引擎"）。本系统只解决"装得下"，不改变玩法骨架。

**容量目标三档（▲数值待 ARCH-008 校准）**：

| 档位 | 阶段 | 单服注册 | CCU 目标 | 君主数 | AI 成本增长模型 |
|---|---|---|---|---|---|
| C1 起步 | MVP-0 | ≤300 | 30-100 | 2-3 | 基线（$35-90/月） |
| C2 目标 | V1 | 3,000-10,000 | 500-1,500 | 7 | **亚线性**：≈C1 × 3-4（聚合+零 LLM 乡野层吸收主要增量） |
| C3 远期 | V1+ | 10,000-50,000 | 1,500-5,000 | 7+跨服 | 亚线性外推，须先过成本账（铁律二①） |

**亚线性承诺（本系统的核心可验证命题）**：CCU ×10 时，LLM 月成本 ≤ ×4。承载方式见 §4。

## 2. 设计目标与反目标

### 目标

| # | 目标 | 验证方式 |
|---|---|---|
| G1 | **成本亚线性**：LLM 成本增速低于人口增速（CCU ×10 → 成本 ≤ ×4） | 分档容量压测+月账单对照（GDD-S10 三档场景外推） |
| G2 | **全量有意义**：乡野层玩家有独立成长线与政治上升通道（乡野→朝堂），不设"陪玩层" | 乡野层玩家旬活跃留存 ≥ 核心层 ×0.8；跨层流动率可观测 |
| G3 | **核心层稀缺不稀释**：席位/摄政位每国名额固定，不随人口扩容 | 席位名额表为常量；扩容只加国/加服不加席位 |
| G4 | **熔断线内可运营**：任一容量档位下日成本可压进 ¥100/服/日熔断线（v0.9 用户拍板） | 分档预算表+计量熔断联测（S1 §8.2） |
| G5 | **大服体验可讲述**：大容量产出的是更盛大的国运叙事（更大的党争、更烈的合纵），而非更卡顿的世界 | 赛季末史书事件量/玩家叙事引用率追踪 |

### 反目标（本系统明确不做的事）

| # | 反目标 | 理由 |
|---|---|---|
| A1 | **不做万人同图实时战场**：拒绝格子占地/实时行军的表达层，会战仍是节点推进制+集结窗口 | 参考系声明（GDD-0 §一）；实时战场同时引爆工程与成本，个人开发者不可行 |
| A2 | **不做卡牌化人口填充**：不给乡野层上抽卡/体力/日常签到的数值填充玩法，民间玩法是先秦生活玩法（市易、游学、婚丧、乡饮酒礼） | 反卡牌化承诺；数值填充玩法会反向污染"政治参与"的主轴叙事 |
| A3 | **不做"千人同声"的君主**：不因人口增长增加君主对话吞吐——自由对话恒为大夫档以上配额制，扩容只按容量表微调配额 | 君主是"活的"不是"应答机"；配额稀缺性本身即特权感（S1 §4.6） |
| A4 | **不在 MVP-0 提前扛大服成本**：MVP-0 只做 schema 预留（分层标签/活动枚举位），不做乡野层玩法本体 | 铁律二①立项即算账；窗口在 schema 冻结前（GDD-0 §九） |
| A5 | **不做分层隔离的"贫民服"**：乡野层不是低配版朝堂，同一世界同一君主同一国运；分层是参与深度的光谱，不是服务器内分区 | 支柱三君臣共治的完整性；隔离层会制造二等公民感 |

## 3. 系统拆解（4 子模块）

| 模块 | 名称 | 职责 | LLM 依赖 |
|---|---|---|---|
| P1 | **玩家分层引擎** | 依散阶+席位+活跃度维护玩家分层标签（核心/骨干/乡野），驱动权限、UI 与配额分支 | 零 |
| P2 | **乡野层玩法系统** | 民间玩法本体：市易/游学/乡饮酒礼/私斗调解/修渠助耕等，独立成长线通向朝堂 | 零（规则引擎；叙事模板由生成管线预产） |
| P3 | **分层统计聚合器** | 将玩家个体行为按国×阶层×行为类聚合成统计摘要，作为君主四层输入唯一口径 | 零（纯计算） |
| P4 | **容量与预算联动器** | 容量档位感知：按 CCU/注册数切档，联动限频、配额、批处理并发与熔断线计量 | 零 |

**依赖声明**：P3 是 GDD-S1 M2（行为聚合）的容量化改造而非并列系统；P2 的成长出口汇入 GDD-S5 声望体系（乡野活动计事功权重，见 §4.3）；P4 消费架构侧网关计量（ADR-001 B3）。**P1/P3/P4 零 LLM——本系统自身几乎不产生 AI 成本，它的全部价值是让别的系统在大容量下不产生 AI 成本。**

## 4. 核心机制与数据规格

### 4.1 玩家金字塔（P1 分层标签）

```
            ┌─────────────┐
            │  摄政/次席   │ 每国 1+1，恒定稀缺
            ├─────────────┤
            │  职事席位    │ 每国 7 席（V1 全席位），恒定稀缺
   核心层   ├─────────────┤
  （朝堂）  │ 卿大夫档     │ 散阶 5-8 档：廷议/推举/自由对话资格（v0.9 门槛）
            ├─────────────┤
            │ 士档（散阶1-4）│ 接诏+上书+任务潮主力；向大夫档晋升
            ├─────────────┤
   乡野层   │ 门客/布衣    │ 民间玩法+任务潮可接；成长出口通向士档
  （民间）  │             │ 低活跃托管：客卿 BYO 主力用户（S7 v0.9 注记）
            └─────────────┘
```

**分层标签规则**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `stratum` | enum(`CORE_COURT` / `CORE_RISING` / `RURAL`) | 核心朝堂（卿大夫档+席位+摄政）/ 核心后备（士档+旬活跃达标）/ 乡野层 |
| `activity_tier` | enum(`DAILY` / `WEEKLY` / `LAPSED`) | 活跃分档（按旬活跃天数），供聚合器加权与流失预测 |
| `rural_xp` | float | 乡野层独立成长值（民间玩法产出） |
| `court_path_ref` | ref | 乡野→朝堂的晋升通道：rural_xp 达阈值可获"举于野"声望加成直入士档中段（GDD-S5 日常任务权重 0.9 的来源扩展） |

**分层语义（防 A5）**：`stratum` 只影响**可参与的动作集合深度**（乡野层不上书议政但可旁听廷议公告、可接诏令转译的民间任务），不影响声望量纲与国运权重——乡野活动的国力贡献与朝堂任务同口径入五维（S2 归因链），"为国耕战者皆是臣"。

### 4.2 乡野层玩法（P2，先秦民间生活线）

**设计原则**：零 LLM 实时成本、叙事模板预产、与国运强耦合（不是挂机收菜的平行世界）。

| 玩法 | 机制内核 | 国力挂钩 | 朝堂接口 |
|---|---|---|---|
| 市易（商旅） | 城邑物价周期波动，玩家跑商囤积 | 经济维贡献（聚合入城邑产出） | 司徒可发"平准令"调节（席位权限示例） |
| 游学（士人） | 列国学宫巡访，答题/辩论小游戏 | 文化维贡献 | 太史录名；文声望小额 |
| 助耕修渠 | 民生任务潮的民间侧（不占任务潮配额，常驻池） | 民生维贡献 | 短板触发时常驻池自动加权（与五维短板联动，S2） |
| 乡饮酒礼 | 社交集会（组队/结义/婚丧），产出社交资产 | 无直接 | 结义网络供恩怨账本二度人脉（S1 M8 检索） |
| 私斗调解 | 民间纠纷事件，玩家任"里正"调解 | 民生/外交小额 | 处置记录入列传（叙事资产） |

**规则引擎承载**：全部玩法为确定性数值+模板化文案（生成管线预产 × 国 × 玩法 × 场景，生成优先铁律二③）；只有"举于野"晋升、里正调解等**高光时刻**触发小模型单条叙事（每旬全国 ≤N 条，N 随容量表定，计入旬决策批处理同批）。

### 4.3 分层统计聚合器（P3——容量与成本的头号锚点）

**原则**：AI 君主 prompt 中的玩家数据**只存在聚合形态**，个体条目仅两种例外（见下）。

**聚合口径（对齐 GDD-S1 四层输入第②层"玩家行为聚合"）**：

| 聚合维度 | 输出字段（每国每旬） | token 预算 |
|---|---|---|
| 分层×行为类 | `count_by_stratum_tasktype`（如"乡野层民生任务完成率 62%，环比 -8pp"） | 恒定，不随人口变 |
| 上书统计 | 上书量/议题分布/采信倾向（已有 M2 口径） | 恒定 |
| 分层健康度 | 各层活跃率/流动率（核心后备↑乡野↓等趋势一句话） | 恒定 |
| 高光个体 | **例外 ①**：旬度 Top-K 政绩者（K=5，K 恒定）——策功/军功榜首以"贤才名录"入 prompt | 恒定（K 不随人口变） |
| 恩怨条目 | **例外 ②**：S1 M8 恩怨账本仅列玩家君主**有直接交互记录**者（有叛逃/上书/会战接触史），陌生人永不入账 | 上限 50 条恒定 |

**成本数学（亚线性证明骨架 ▲待 ARCH-008 验证）**：旬决策主 prompt 的玩家层 token = 五维摘要（恒定）+ 聚合统计（恒定）+ Top-K + 恩怨 ≤50（恒定）→ **与人口无关**；人口增长只影响：批处理并发（规则引擎零 LLM 不受影响）、乡野高光小模型条数（线性但单价极低，容量表内配额封顶）、客卿 BYO（玩家自付）。故 LLM 成本对人口近似 O(1)+O(小 K 线性)，CCU ×10 → 成本 ≤ ×4 承诺成立的前提是 P3 严格执行。

### 4.4 容量与预算联动器（P4 弹性参数表 ▲）

| 参数 | C1（30-100 CCU） | C2（500-1,500 CCU） | C3（1,500+ CCU） | 联动系统 |
|---|---|---|---|---|
| 旬长 | 7 天 | 7 天（可缩至 3 天，成本账先行） | 3 天 | S1/GDD-0 §4.4 |
| 乡野高光小模型条数/旬 | 10 | 30 | 60 | P2 |
| 自由对话配额 | —（V1 前） | 大夫档 3/日 | 大夫档 2/日+候补队列 | S1 §4.6 |
| 客卿限频上限（BYO） | 500 动作/日 | 800/日 | 800/日+排队 | S7 |
| 会战集结窗口 | 24h | 48h | 72h | S3 |
| 计量熔断线 | **¥100/服/日（v0.9 用户拍板，恒定硬上限）** | 同左 | 同左 | S1 §8.2 |
| 进程模型 | 单进程队列 | 分离队列+读写分离 | 分服+跨服网关 | ARCH-008 |

**切档规则**：以"连续 2 旬 CCU 峰值超档位上限 80%"触发升档评估，升档先出成本账（铁律二①）再动参数；降档随时可回。熔断线 ¥100/服/日为恒定硬顶，任何档位不得突破——超限时 S1 D1→D3 降级链自动接管。

## 5. 玩家交互流程与 UI 呈现要点

| 层 | 玩家身份 | 关键交互 | UI 锚点（视觉锚点对齐） |
|---|---|---|---|
| 乡野层·新玩家 | 布衣 | 开局入乡野：选生计（市易/游学/助耕），旁听国策诏布告 | 水墨村镇卷轴；布告栏以竹简阵列呈现诏书摘要 |
| 乡野层·成长 | 门客 | 乡野玩法积累 rural_xp，触发"举于野"事件 | 县乡三老举荐的缯帛文书仪式（对齐锚点②） |
| 跨层流动 | 士 | rural_xp 阈值→声望直入士档中段→接诏入任务潮 | 升档时"名入士籍"简牍动画 |
| 核心层 | 卿大夫以上 | 既有朝堂玩法全量（S1/S5/S8），无变化 | 朝堂烛火（锚点④） |
| 全体 | — | "国用丰俭"页展示本服容量档位与成本叙事（"仓廪实/用度紧"） | 国库计量=半透明成本治理（S1/铁律二⑤） |

**关键 UX 原则**：分层对玩家**可感知但不羞辱**——乡野层 UI 主视觉是"野有遗贤"的机会感（"三老议君之才"），而非"你不在名单上"的排斥感；跨层门槛永远显示为下一次可达成的事件，不是灰色锁。

## 6. 边界与依赖

**上游依赖**：GDD-S1 M2（行为聚合——P3 是其容量化实现）；GDD-S5（声望体系——乡野活动入事功口径、"举于野"入八档门槛表注记）；GDD-S3（会战——集结期民间侧与 P2 助耕/造械共享常驻池）；GDD-S7（客卿——乡野层 BYO 主力，限频参数取 P4 表）；GDD-S10（MVP-0 范围与铁律二）。

**下游被依赖**：GDD-0 §一参考系声明（容量承载方案）、§九大服-ready 原则、§十风险 12 缓解；架构侧 ARCH-008（容量压测与档位校准的唯一需求来源——见 §8.2 移交清单）。

**不覆盖**：跨服会盟（远期愿景，本系统仅预留 C3 行"分服+跨服网关"占位）；多端/客户端性能（工程域）。

**架构可实现性红线（与程基岩对齐项）**：① P3 聚合必须为**旬快照时点物化视图**（与旬决策冻结语义一致，S1 §4.4），非实时查询；② 恩怨 ≤50 条与 Top-K=5 为**服务端硬截断**，不可配置放大；③ 分层标签变更有旬内延迟可接受（与"旬内换官按快照"同语义，GDD-0 §4.3）。

## 7. MVP 裁剪

**MVP-0 只做三件事（其余全部推迟）**：
1. **schema 预留**：玩家表加 `stratum`/`activity_tier` 枚举位；活动表加 `rural_type` 枚举位（A4——窗口只在 schema 冻结前）；
2. **P3 最小版**：聚合口径按"全员视为 CORE_RISING"退化执行（MVP-0 人口小，聚合≠过滤），但**聚合接口形态必须与大服版一致**（同名函数同签名，内部退化实现）；
3. **P4 最小版**：仅熔断线 ¥100/服/日 计量+降级链（已有 S1），无切档。

**MVP-0 不做**：乡野层玩法本体（P2）、分层 UI、跨层流动、举于野——V1 按 C2 档成本账解锁（乡野层为 V1 首批扩容项：它同时服务留存与容量，性价比最高）。

**MVP-0 砍留原则**：砍的是玩法，留的是**形状**——所有 V1 乡野系统必须能装进 MVP-0 预留的 schema 里，不需要数据迁移。

## 8. 验证指标

### 8.1 系统级指标

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 成本亚线性比 | CCU ×10 时 LLM 月成本 ≤ ×4 | 分档账单对照（G4） |
| 单旬主 prompt token | 玩家层 ≤ 恒定预算（数值▲ARCH-008），不随注册数变化 | 网关计量按 prompt 段拆分 |
| 乡野层旬留存 | ≥ 核心层 ×0.8 | 分层活跃报表（G2） |
| 跨层流动率 | 每旬乡野→士档转化 ≥2%（V1 后观测） | stratum 变更日志 |
| 熔断触发率 | 月内触发 D3 次数 ≤2 | S1 §8.2 告警 |
| 席位稀缺常量 | 席位名额/国 = 表常量，差异 = 0 | 配置审计 |

### 8.2 移交架构侧的容量需求清单（ARCH-008 输入）
