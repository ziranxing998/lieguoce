## 1. 系统概述

**一句话**：任务系统是**国策的执行面**——它消费 S1 任务潮需求单，把每旬《国策诏》的国家目标实例化为可接取的"差事"（任务实例），承载玩家的接诏-办差-回奏闭环，把执行结果以结算事件交 S2 双轨账本归因，是玩家与 AI 君主之间**频率最高**的接触面。

**在数据流中的位置**：

```
[S1 M5 任务潮需求单(规则引擎池+LLM权衡)] ──需求单──→ 【GDD-S12 任务系统】 ──settlement_event──→ [S2 N2/N3 收益结算与双轨归因]
        [S1 国策诏/M4 事件诏令] ──诏令目标 ref_goal_id──↗          │
        [S5 散阶/席位] ──差事上限+判定加成──↗                      ├─→ [S3 会战] 战时 war_side 推进度申报
        [S7 客卿网关] ──task 接取/执行调度(白名单)──↗              ├─→ [S1 M2] task_completion_rate 行为聚合回流
                                                                  └─→ [S5 P1] 声望流水(TASK 来源)
```

- 它**不产生**任务需求（S1 M5 职责，反目标 A6 双头内容源防线）、**不拥有**国力数值与归因账本（S2 职责）、**不换算**声望（S5 P2 职责）、**不裁决**会战胜负（S3 职责，战时任务只申报推进量）。
- 它是支柱一"君主是活的"在 L1 层的**日常载体**：玩家每旬打开的每一张差事竹简，都是"君主这旬在想什么"的具象表达；也是支柱二"国运涌现"的最上游执行泵——没有差事被办掉，五维衰减就不会被对冲，国运无从涌现。

## 2. 设计目标与反目标

### 目标（按优先级）

| # | 目标 | 验证方式 |
|---|---|---|
| G1 | **任务是国策的执行面，不是章节任务板**：每个任务实例必须绑定诏令目标（`ref_goal_id`），玩家能从差事卡看到"此事应哪道诏" | `ref_goal_id` 非空率 100%（工程验收）；任务卡"应诏"标签点击率埋点 |
| G2 | **两档做法是真权衡**：全力/省力构成"风险-确定性"光谱，无最优解 | 全力/省力选择比落在健康带（见 §8.1）；问卷"办差选择有取舍"≥ 3.8/5 |
| G3 | **旬制节拍承载**：差事随旬发布、旬末过期、进旬重定策——任务的呼吸与君主决策同步 | 旬内过期不接率、进旬刷新及时率 |
| G4 | **防刷与稀缺**：差事上限按官职联动（上大夫双差），收益递减（S2 N4）与单维占比上限（S1 M5）在本系统的供给端不变通 | 上限绕过尝试 = 0（服务端强制）；同维办差集中度 ≤ 35% |
| G5 | **战时动员感**：战时任务全部挂 `war_side`，办差可感知地推进/守住战线 | 战时任务响应率、战线推进归因可追溯 |

### 反目标（本系统明确不做的事）

| # | 反目标 | 理由 |
|---|---|---|
| A1 | **不做"为任务而任务"的内容**：无诏令来源不生成任务；不做日常/周常清单、签到式任务 | 支柱一红线：任务清单化会让君主沦为"任务发放器"（GDD-0 支柱一一票否决项）；任务潮永由国力短板+人格+需求单驱动 |
| A2 | **不做手动刷新任务池**：玩家不能重掷本旬任务列表，不接的任务自然过期 | 防刷 + 旬制节拍（G3）；"不满意的差事"本身是君心参悟素材 |
| A3 | **不拥有结算与归因**：本系统只发 `settlement_event`，收益入账、递减修正、策功/事功记分全在 S2 | 单一口径（S2 N3 双轨账本唯一权威）；本系统记第二本账必然出叉 |
| A4 | **不做限时秒回玩法**：任务时限以旬为最小单位，无倒计时压迫 | 与旬制决策节拍（S1 A5）一致；成本与体验双收敛 |
| A5 | **不给客卿 API 独占任务**：无专属差事、无 AI 裁定加权（对齐 S7 A4） | 公平底线；客卿在任务系统的全部权限 = 手动权限子集（GDD-0 玩家主权原则） |

## 3. 系统拆解（6 子模块）

| 模块 | 职责 | 输入 | 输出 |
|---|---|---|---|
| T1 任务模板库与实例化 | 模板库管理；需求单→任务实例的确定性实例化；LLM 生成路径的包装与校验 | S1 需求单、模板库、人格语气包 | 任务实例（OPEN 态） |
| T2 任务潮需求单对接 | 消费 S1 M5 两级结构；摄政优先级透传；战时豁免参数承接 | S1 `TaskWaveDirective` | 本旬实例化配额与抽取排序 |
| T3 执行判定 | 全力/省力两档判定；官职加成；结果判定 | 接取请求、玩家档位、任务参数 | 判定结果（成/败·收益档） |
| T4 结算与归因 | 组装结算事件交 S2；战时推进量申报 S3；声望流水交 S5 | 判定结果、任务声明 | `settlement_event` / `war_progress申报` / 声望流水 |
| T5 差事上限与官职联动 | 按散阶档位执行旬差事上限；上限的前置校验 | S5 档位、本旬办差记录 | 可接/已满状态 |
| T6 战时任务变体 | 战时任务标记 `war_side`；后勤/军事分类对齐 S1 REV-004 豁免口径；推进申报 | 战争状态（S3）、需求单 | 战时任务实例 + 推进申报 |

### 3.1 T1 任务模板库与实例化

- **双源生成**（对齐试玩版现状，纳入成本敏感原则③"生成优先"）：
  1. **LLM 生成路径**（主路径，旬度批处理内与《国策诏》同一次调用产出）：S1 M3 决策主调用的输出含本旬 3 条任务（标题/描述/文武/维度/基准收益 5-15），本系统做**结构校验 + 数值夹取**（`reward` 夹至 [3,15]、`dim` 白名单校验、`type` ∈ {文,武}，试玩版同规则）后实例化；
  2. **模板池兜底路径**：LLM 失败/超限时，按 S1 M5 规则引擎抽取的短板维度，从模板库抽取同维模板实例化（试玩版 `templateDecreeFull` 的 pools 结构规格化）——**保证"每旬必有可办差事"**（与 S1"每旬必有国策诏"节奏承诺同构）。
- **实例化必填规则**：每实例必须回填 `ref_goal_id`（LLM 生成任务由 S1 输出结构携带；模板任务绑定为该短板维度生成的默认诏令目标）；无可用诏令目标时**不生成**该实例（对齐 A1——宁可差事少，不可任务板化）。
- **人格语气包装**：任务描述语由 S1 M5 权衡层按 7 国人格 × 任务类型变体生成（模板库 `variant_pool` 承载），任务数值与文案同源自 S1，杜绝"数值 A 文案 B"的人格漂移。
- 兜底链与 S1 降级链（主模型→备用模型→冻结上旬→模板诏令）对齐：模板池任务复用上旬有效期内的诏令目标（2 旬归因窗口内有效），保证归因链不断。

### 3.2 T2 任务潮需求单对接

- 消费 S1 M5 两级结构：**规则引擎池**（确定性、含 40% 单维占比上限、战时 60% 豁免）+ **LLM 权衡**（主推方向与叙事）。本系统是需求单的**唯一下游实例化方**，不二次加权、不改配额——权重底数属 S1，改了必破坏"短板-任务潮相关性 ≥ 0.7"的验证口径。
- 摄政干预（S1 M6）：`regent_override.priority_order` 透传为实例的下发排序（齐国 MVP 试点），本系统不改权重。
- **"不生成任务"条款（上游约束的镜像确认）**：方略树（GDD-0 §五文明系转译）是国家级长期线，**不生成任务、不占任务潮配额**（S2 v0.10 注记）——本系统不接收任何来自方略树的直发请求，方略收益走 S2 归因链不经本系统。两线关系："方略树改权重与曲线（河道疏浚），任务潮管旬级执行（防汛调度）"。

### 3.3 T3 执行判定（两档做法）

- **两档做法是"风险-确定性"光谱**（判定参数见 §4.4）：
  - **全力办**：高成功率（0.78），成功得全额收益；失败得 40% 收益（差事办砸但未全废——"尽心而事不谐"）；
  - **省力办**：必成（p = 1.0），恒得 40% 收益。
  - 期望收益：全力 = 0.78×1.0 + 0.22×0.4 ≈ **0.87** vs 省力 = **0.40**——全力在期望上仍占优，省力的价值是**确定性**（低档位/战时高压/怕策罪连坐时锁底）；两者非对称，无主导策略。
- 【勘误】试玩版 `completeTask` 中两档共用同一掷骰（`roll<0.78` 对 choiceIdx 不敏感），省力档实际也会失败且成功得全额——正式版按上表修正：省力=必成 40%。
- **官职加成（▲建议，数值策划标定）**：大夫档 +5pp、上大夫及以上 +8pp（全力办成功率封顶 0.90）；战时军事/后勤类任务，持武席位（上将军/司马）者另 +5pp。加成只作用于全力档——官越大越敢任事，省力档不加成（官职是担责的资本，不是摸鱼的特权）。
- **取巧惩罚（▲建议）**：省力办无即时数值惩罚（惩罚即机会成本 0.47 差额）；人格记忆侧写为软约束——对 `player_affinity.despise` 含 `OPPORTUNISM` 的君主（如秦），连续 2 旬全取巧 → 恩怨账本软记忆 intensity +0.1/次（S1 M8 既有管线，无新机制），表现为复盘语录冷淡与晋升诏评语降格。不做硬惩罚（防止把人格写成数值开关）。

### 3.4 T4 结算与归因

- 结算三分制沿用 S2 N2：`实际收益 = 声明基准 × 质量系数 × 递减修正`——本系统只产出**结算事件**：`settlement_event(task_id, executor, quality)`，`quality` 由判定结果映射（全力成=1.0 / 全力败=0.4 / 省力=0.4）。
- **双轨归因同源**：任务实例的 `ref_goal_id` 使一份结算事件同时喂 S2 策功链（提案人）与事功链（执行者）——"文武账本同源不出叉"（S2 §4.5 第 3/4 条）。
- **声望与国力解耦**【勘误】：试玩版将 `reward` 同时用于国力增量与声望增量（`gain = ok ? task.reward : reward/2`）——正式版解耦：国力走声明基准（5-15，S2 口径），声望走 S5 P2 固定额度 **2-5 点/次（TASK 来源，w=0.9）**，防 LLM 生成的 reward 数值直接放大成声望通胀。
- 战时：`war_side` 任务的推进量随结算事件申报 S3（攻 +/守 −，申报量 = 实际收益），会战胜负与节点推进判定全在 S3，本系统不裁。

### 3.5 T5 差事上限与官职联动

- 上限规则：**上大夫档及以上每旬 2 件，其余 1 件**（对齐试玩版"领双差"特权、对齐 S5 §4.3 散阶表——双差是上大夫的档位特权之一）。
- 【勘误】试玩版以 `rankIdx>=6` 判定（实际命中上卿），与文案"欲领双差，须升至上大夫"有一档偏差——正式版按档位枚举判定（`rank >= SHANG_DAFU`）。
- 服务端强制（A4）：上限校验在接取事务内完成（本旬 `action_type='task'` 计数），不信任客户端。
- 与 S5 联动：档位变更旬初朝会生效（快照语义，对齐 REV-003"旬内换官按快照时点在任者生效"）；降档后已接任务不收回，本旬剩余配额按新档计。

### 3.6 T6 战时任务变体

- 触发：S3 会战实例状态 ∈ {DECLARED, BATTLES} 期间，该国需求单强制全量战事化（对齐试玩版：宣战当旬 3 任务全部与战事相关）。
- `war_side` 标记：攻方国玩家任务 `attack`、守方 `defend`、中立第三国 `null`（试玩版规则规格化）。
- **豁免口径一致性**：战时任务中军事/后勤类（`war_tag ∈ {MILITARY, LOGISTICS}`）受 S1 REV-004 60% 占比豁免与 S2 REV-005 递减放宽（r=0.8）保护——三系统同一口径清单，防"池里全是支前任务但玩家刷不动"的断裂（S2 §4.2 战时条款的供给端确认）。
- 战时差事上限**不放宽**（每旬 1-2 件不变）——动员感靠任务质变（全战事化+战线推进），不靠量变（刷差事数量），与 N4 递减防刷红线一致。

## 4. 数据规格

### 4.1 任务实例 schema

```json
{
  "task_id": "t_qin_x14_003",
  "xun": 14,
  "lord_id": "qin",
  "ref_edict_id": "qin_x14_edict",
  "ref_goal_id": "g1",
  "title": "督办粮草",
  "desc": "征发民夫转运军粮至前线",
  "type": "WEN | WU",
  "dim": "economy",
  "declared_gain": {"base": 8, "quality_factor": 1.0},
  "prestige_reward": {"min": 2, "max": 5},
  "war_side": "ATTACK | DEFEND | null",
  "war_tag": "MILITARY | LOGISTICS | null",
  "template_id": "tpl_qin_logistics_01 | null",
  "llm_generated": true,
  "choices": ["QUANLI", "XINGLI"],
  "status": "OPEN | TAKEN | DONE | FAILED | EXPIRED",
  "executor": "u_10244 | null",
  "agent_flag": "MANUAL | AGENT_ASSIST | null",
  "deadline_xun": 14,
  "created_at": "…"
}
```

**状态机**：

```
OPEN ──接取(T5 上限校验)──→ TAKEN ──判定(T3)──→ DONE（quality=1.0 或 0.4）
 │                            │
 └──旬结算未接──→ EXPIRED     └──旬结算未判定(离线且无守舍之约)──→ EXPIRED（不计失败、无惩罚，仅机会成本）
DONE/FAILED ──结算事件──→ S2；实例归档（透明日志可查，跨季匿名化对齐 S1 §6.5）
```

- 判定即时完成（试玩版同步办差保留），"失败"是判定结果不是滞留状态；EXPIRED 是唯一"没办成"的滞留出口且无惩罚——先秦语境"差事没赶上点卯"不罪，防离线惩罚劝退。

### 4.2 模板库字段表

| 字段 | 类型 | 示例值 | 说明 |
|---|---|---|---|
| `template_id` | string | `"tpl_qin_logistics_01"` | 唯一 ID |
| `lord_scope` | array | `["qin"]` 或 `["ALL"]` | 适用国/人格（人格原型卡可共用 `ALL`） |
| `type` | enum | `"WU"` | 文/武 |
| `dim` | enum | `"economy"` | 收益维度（五维枚举，MVP 三维） |
| `base_reward` | int | `8` | 声明基准（3-15） |
| `title_template` / `desc_template` | string | `"督办{物资}至前线"` | 参数化文案 |
| `variant_pool` | array | 7 国人格语气变体引用 | 叙事包装（对齐 S1 M5） |
| `war_tag` | enum | `"LOGISTICS"` | 战时豁免口径分类 |
| `war_side_applicability` | array | `["ATTACK","DEFEND"]` | 可用于攻/守侧 |
| `min_rank` | enum | `"SHIDAFU" | null` | 官职门槛（默认无——A5 反独占） |
| `weight` | float | `1.0` | 模板抽取权重（S1 draw 消费） |

- 模板资产量（V1）：7 国 × 5 维 × 文武 ≥ 2 变体 ≈ **140+ 条**，走 LLM 生成管线 + 5-10% 抽检（铁律二③）；MVP 仅 3 国 × 3 维 × 各 3 条 ≈ 27 条（试玩版 pools 直接升级）。

### 4.3 成功率参数表（首版标定 ▲，入 N7 同级 GM 调参清单）

| 参数 | 值 | 说明 |
|---|---|---|

| 声望质量映射 | 全力成 1.0 / 全力败 0.5 / 省力 0.5 | 作用于 TASK 固定额度 2-5 点（S5 口径）【勘误：试玩版失败声望=1/2 额，正式版省力同折】 |

## 5. 玩家交互流程

| 场景 | 流程与体验要点 |
|---|---|
| **布衣看板**（旬初朝会） | 国策诏卷轴展开（视觉锚点②）→ 诏下列本旬差事竹简卡：标题、文/武印鉴、宜利（"民生 +8"竹简标签钉卡，S2 UI 口径）、**"应诏 g1"标签**（点击展开诏令原文——G1 的玩家侧验证面）、战时 ⚔ 标记与攻/守侧标注 |
| **办差** | 选差事 → 两档选择卡：**「尽心办」**（副文："全力以赴，成败在天"，展示成功率与全额宜利）与**「循例办」**（副文："循例应差，稳而功半"，展示必成与 40% 宜利）→ 办差中（不得同时办第二件，上限校验先行） |
| **结果反馈** | 回奏文书（`player_actions.note`："督办粮草·尽心办·成，攻势推进"）→ 国力五维即时可见变化 → 声望/晋升提示（"官升一级"演出沿用试玩版）→ 战线推进提示（"边城陷落/守御奏效"，战时强反馈） |
| **旬末过期** | 进旬时未办差事灰化归档，提示"上旬未竟之差，已入档"——不惩罚、不红字（§4.1） |

**两档做法正名（试玩版 → 正式命名建议）**：
- **「尽心办」保留**（对应"全力"）——先秦君臣语感准确，与 S5"功过对称"叙事同向；
- **「取巧办」正名为「循例办」**（对应"省力"）——理由：① "取巧"在先秦与人格卡语境中含明确贬义（秦君 `despise: OPPORTUNISM`），玩家会预期道德惩罚，而机制上省力是无惩罚的确定性选项，**名实不符**；② "循例"= 按章程应差，中性、稳、无咎——恰是 40% 确定收益的机制语义；③ 保留副文"省力而功半"延续试玩版认知。
- 状态标记：▲ 命名建议待用户拍板（若用户坚持"取巧办"，机制不变，仅人格侧写强度上调至 -0.15/次以名实相符）。

## 8. 验证指标

### 8.1 核心指标

| 指标 | 定义 | 目标值 | 采集 |
|---|---|---|---|
| **任务完成率** | 旬内发布差事中被办掉（DONE）的比例 | ≥ 70%（低于此说明供给与玩家错配或上限过紧） | 结算日志 |
| **取巧率** | 省力办选择占全部办差次数比例 | **30%-50% 健康带**：<30% = 确定性价值不存在（两档名存实亡）；>50% = 全力期望/惩罚失衡或高风险疲劳 | 办差日志 |
| **维度均衡度** | 办差维度分布 vs 需求单权重分布的皮尔逊相关 | ≥ 0.7（与 S1 G3 短板相关性对表——本指标是它的下游验收） | 数据后台 |
| **两档选择风险偏好分群** | 高档位（大夫+）玩家全力率 − 布衣全力率 | ≥ 10pp（官职加成被感知的证据） | 分群监控 |
| **战时任务响应率** | 战时差事办掉比例 vs 平时 | ≥ 平时水平（动员感成立）；战时军事/后勤类占比与 60% 豁免口径一致 | 结算日志 |
| **"应诏"标签点击率** | 任务卡应诏标签点击 / 办差 UV | ≥ 25%（G1"执行面"感知） | 埋点 |
| **上大夫双差使用率** | 上大夫旬内办满 2 件比例 | ≥ 50%（档位特权有效） | 结算日志 |

### 8.2 护栏指标

| 指标 | 阈值 | 说明 |
|---|---|---|
| 上限绕过尝试 | 0（服务端强制，出现即事故） | A4 红线 |
| 客卿/手动独占性检查（V1） | API 玩家可触达任务集合 = 手动玩家集合 | S7 §8.1 同口径，工程验收 |
| 结算事件与归因链对账差 | 0（每笔 DONE 可回溯 ref_goal_id 与 S2 delta_events） | S2 归因可追溯率 100% 的本系统侧 |
| 模板兜底触发率 | ≤ 20%（高于此说明 LLM 管线故障或成本熔断常态，告警） | 与 S1 降级率联动 |
| 过期无惩罚投诉 | 旬度舆情监测 | EXPIRED 不计失败的红线被误伤即修文案 |

### 8.3 复盘机制

- 每旬任务侧快照（需求单 vs 实例 vs 判定结果 vs 结算事件）落盘，与 S1 决策快照同库——构成"诏-务-效"回放链，供 S2 归因复盘与史书"名臣列传"事迹取材三用。
