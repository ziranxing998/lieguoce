## 1. 系统概述

**一句话**：朝堂与廷议系统是玩家**政治活动的舞台系统**——它不裁决任何事，它负责把玩家的一切政治行为（上书、议政案、廷议议题、联署、推举票）**聚合、排程、公示**：上书经去重统计回流 S1 君主决策输入，议政案结构化后进入 S2 策功归因链，廷议按旬排程对接 S8 仲裁流程，推举票对接 S5 选举事务——朝堂是"君臣共治"支柱的**物理场所与公共舆论广场**。

**在整体中的位置**：
- 它是支柱三"君臣共治"的**舞台层**：S5 造阶发牌、S8 定仲裁规则、S1 出 AI 立场——这些"权力系统"都需要一个玩家看得见、进得去、可复盘的公共空间，这个空间就是朝堂。
- 它是支柱一"君主是活的"的**输入聚合器**：玩家上书的统计倾向是 S1 M2 四层输入第②层的直接来源（GDD-0 §4.2"上书统计倾向"），朝堂保证这股输入**去重、防刷、可审计**。
- 它**不裁决**（廷议胜负归 S8、AI 立场归 S1、声望换算归 S5）、**不执行**国力效果（S2）、**不决定**外交效果（斡旋判定归 S6，朝堂只供入口）。

```
[玩家政治行为] 上书 / 议政案 / 廷议议题 / 联署 / 投票
        │
        ▼
【GDD-S13 朝堂与廷议】（聚合 · 排程 · 公示）
   ├─ C2 上书聚合 ──petition_tendency（去重票）──→ [S1 M2 决策输入]
   ├─ C3 议政案 ──proposal 结构 ──→ [S2 策功归因链] → [S1 M3 诏令裁夺]
   ├─ C1 廷议日程 ──议题排程 ──→ [S8 R5 廷议仲裁] ←─ 立场分/反对理由 ── [S1 M6]
   ├─ C4 选举事务 ──推举票/联署 ──→ [S5 P4/P5] / [S8 R6 弹劾]
   └─ C6 朝堂公示 ──诏令/置顶/透明日志入口/排行榜 ──→ 全国玩家
```

## 2. 设计目标与反目标

### 目标（按优先级）

| # | 目标 | 验证方式 |
|---|---|---|
| G1 | **上书必被听见**：上书经统计回流后，玩家在下旬诏令/语录中能看到"君主参考了大家的意见"的反馈（对齐 S1"上书-反馈闭环感知"） | 上书玩家反馈感知问卷 ≥ 3.8/5（S1 §8.1 复用） |
| G2 | **朝堂是公共广场而非私信箱**：议政案、廷议记录、推举结果全程全国可查，政治行为有观众 | 朝堂公示页周打开率 ≥ 30% |
| G3 | **聚合可信防刷**：上书倾向去重（单玩家旬内同议题计 1 票）、单玩家影响 ≤5% 上限在朝堂侧强制执行 | 刷量票作废率 100% 拦截；聚合日志可审计 |
| G4 | **官阶=朝堂话语权阶梯**：各档位在朝堂能做的事差异清晰、门槛可见（"君前奏对，乃大夫之礼"式预告而非灰色隐藏） | 档位-权限映射页面渗透率；升档动因问卷 |
| G5 | **廷议是旬制节拍的政治仪式**：议题随旬排程、旬末归档，与"朝会时刻"（S1 旬初诏令发布）形成节奏闭环 | 廷议议题旬内按时开议率 ≥ 99% |

### 反目标（本系统明确不做的事）

| # | 反目标 | 理由 |
|---|---|---|
| A1 | **朝堂不裁决**：AI 立场分与反对理由归 S1 M6，撤回/强推判定归 S8 R5，选举计票有效性归 S5 P5——朝堂只提供日程、聚合与公示 | 职责单一；裁决权分散三处是"共治博弈"的结构，聚到一处就成了第二君主 |
| A2 | **不做自由论坛**：朝堂内一切政治输入为**结构化选项**（议题标签/建议卡/投票/联署），无自由灌水区（自由对话仅 S1 §4.6 三场合、大夫档+、V1） | GDD-0 §4.4 定稿；自由文本入决策流=人格漂移+成本失控+注入风险三重灾难 |
| A3 | **不隐藏话语权阶梯**：未达档玩家看到的是锁定态与达成预告，不是默默隐藏的功能 | 对齐 GDD-0 §4.4"正向包装"原则；隐藏门槛=劝退 |
| A4 | **不做上书直达裁决**：上书是统计倾向票，不是工单；玩家不能要求君主"回复我的上书" | 支柱一红线：君主按人格与国力决策，不做玩家需求应答机；被采纳感靠下旬诏令语录闭环 |
| A5 | **不重复拥有数据**：上书原文归玩家行为日志、议政案归 S2 提案表、廷议归档归 S8 廷议档案、票归 S5——朝堂页全部引用不复制 | 单一口径；朝堂存第二份副本必出叉 |

## 3. 系统拆解（6 子模块）

| 模块 | 职责 | 输入 | 输出 |
|---|---|---|---|
| C1 廷议日程与议题池 | 每旬廷议议题的生成、排程、归档 | 摄政发起权（S8）、AI 生成议题（S1）、固定议程 | 廷议日程表（交 S8 R5 走仲裁） |
| C2 上书聚合器 | 上书收集、去重计票、≤5% 上限、旬度聚合 | 玩家上书（结构化卡） | `petition_tendency`（回流 S1 M2） |
| C3 议政案事务 | 议政案的呈递、结构化校验、状态流转、裁夺公示 | 大夫档玩家/客卿代拟稿 | 议政案记录（→ S2 提案结构） |
| C4 选举事务 | 推举票资格校验、联署收集、投票窗口排程 | S5 资格规则、S8 弹劾流程 | 联署名册/投票名册（计票归 S5/S8） |
| C5 朝堂信息展示 | 诏令张贴、摄政置顶、透明日志入口、政绩排行 | 各系统只读数据 | 朝堂主界面 |
| C6 朝堂入口路由 | 斡旋/任务/对话等入口的档位校验与路由 | S5 档位、各系统白名单 | 入口放行/锁定预告 |

### 3.1 C1 廷议日程与议题池

- **旬制排程**：每旬朝会时刻（旬初，与 S1 诏令同刻）开列本旬廷议议程；旬末归档。**每旬每国议程上限 3 项**（防议题泛滥稀释参与感 ▲标定）。
- **议题三来源**：
  1. **摄政发起**（每旬 1 次，S8 R3 四权限之一）——正式版走 S8 R5 仲裁全流程；MVP 表达为**摄政置顶裁夺**（见 3.4）；
  2. **AI 生成**（S1 M3 旬决策附带"本旬可议之政"候选 0-2 条，人格驱动——秦议军制、齐议稷下）；
  3. **固定议程**（短板触发：CRITICAL 维自动入议程——"仓廪告急，朝野共议"，与 S2 N5 危机叙事事件联动）。
- **议题结构**：复用 S2 提案结构（`dims_target` + 依据），保证任何议题被采纳后可直接进策功归因链——**朝堂里没有"聊完就散"的议题，每条可议之政都是潜在国策**。
- 议题开议时，S1 M6 生成 AI 立场分（-5~+5）与反对理由语录（M7 双审），按 S8 R5 流程走撤回/强推判定——**朝堂只挂"开议/议毕"的牌子**。

### 3.2 C2 上书聚合器（回流 S1 的唯一通道）

- **上书卡结构**：议题标签（枚举，对齐五维+军政议题）+ 一句理由 + 国力依据引用（可选）。MVP 即试玩版形态规格化。
- **去重计票规则**（承接 S1 M2 既有口径，本模块为执行方）：
  - 同一玩家同一议题**每旬计 1 票**（去重防刷）；
  - 上书格位：**布衣 1 格、下士及以上 2 格**（试玩版 `rankIdx>=1 → maxN=2` 继承，文案对齐"升下士可占两格"）——格位是上书广度（可同时保有 2 条倾向），不是票数翻倍：两格=两张不同议题票。
  - **单玩家影响上限 ≤5%**：旬度聚合时按玩家去重后，任一玩家票数占本旬总票数超 5% 部分不计（服务端硬截断，对齐 S11 §6"不可配置放大"红线与 S1 M2 异常剔除）。
- **回流时点**：旬末上书最有效（试玩版 hint 继承）——旬快照冻结时点（旬末）前提交的上书计入本旬 `petition_tendency`，冻结后的滚入下旬。
- **输出**：`petition_tendency`（议题 → 去重票数），字段口径以 S1 §4.2 为准，本模块不另造字段。
- **反馈闭环**：旬决策若采信某议题倾向，S1 M7 语录按"引其意不引其名"规则提及（S1 §4.5），朝堂公示页对当旬上书者展示"君上采纳众议"标记——闭环感知（G1）的落地。

### 3.3 C3 议政案事务

- **定位区分（本 GDD 核心勘误）**【勘误】：试玩版将"上书（倾向票）"与"议政案（一句话国策建议）"共用 `action_type='memorial'` 落库——正式版拆分：**上书 = 倾向统计票**（action_type=`memorial`，进 C2 聚合），**议政案 = 结构化提案**（action_type=`proposal`，走 C3，进入 S2 策功归因链）。两者权重不同：上书影响"君主这旬想什么"，议政案可能直接"采某卿之议"署名入诏。
- **呈递门槛**：**亲笔议政案须下大夫档及以上**（试玩版 `need:4` 继承）；未达档玩家可经**客卿代拟**生成草稿，呈递仍须本人手动（对齐 S7 政治动作可代拟、身份动作须本人）。
- **结构**：MVP = 一句话建议（≤40 字，试玩版 maxlength 继承）+ **维度标签必选**（`dim` 不得为 null——【勘误】试玩版议政案 `dim:null` 落库，正式版必选维度标签，保证可归因）；正式版升级为 S2 提案全结构（议题+依据+目标维度 `dims_target`）。
- **状态流转**：`DRAFTED（草稿/代拟）→ SUBMITTED（呈递）→ ADJUDICATED（诏书裁夺：采纳署名 / 驳回附君心理由 / 存档不议）`。裁夺结果随下旬《国策诏》公示——采纳者走 S2 策功链（"采某卿之议"），驳回者附一句人格化理由（复用 M7 管线，边际成本≈0）。
- **摄政置顶裁夺**：摄政亲笔裁夺的议政案在朝堂展示时**置顶+印鉴标记**（试玩版 `'【摄政亲笔·置顶裁夺】'` 规格化继承）——这是摄政"廷议议题发起权"在议政场景的 MVP 表达 ▲（正式版与 C1 议题发起合并）。
- **限额**：每人每旬议政案 1 件（上书格位管倾向、议政案限 1 管质量——"一旬一策，贵精不贵多"▲标定）。

### 3.4 C4 选举事务（推举票与联署的排程方）

- 朝堂是选举的**排程与收集场所**；计票有效性归 S5 P5、弹劾裁决归 S8 R6（A1 边界）。
- **推举廷议**（季末摄政竞选，S8 R1）：朝堂公示候选人政绩时间线（自动聚合 S2 归因链）→ 有票权者投票（资格三条件校验由本模块执行快照、计票交 S5）→ AI 终审诏公示（含否决君心理由）。
- **席位补选**（S5 P4）：空缺后 1 旬内由朝堂开选，流程同上；MVP 砍（空缺由 AI 直接任命）。
- **弹劾联署**（S8 R6）：次席发起 + 30% 卿大夫联署（7 天窗口），本模块负责联署收集与资格校验（联署是身份基座行为，**不可客卿代签**，A4）；联署达标后开票窗口排程。
- 投票全部**一人一票、投出锁定**（S5 §4.5），匿名展示为票型统计（"某某档联署率 34%"），明细入透明日志。

### 3.5 C5 朝堂信息展示（公示面）

- **必展示项**：本旬《国策诏》全文（诏书仪式感，视觉锚点②竹简帛书）、廷议议程与归档、议政案公示墙（含置顶）、推举/弹劾公告、政绩排行榜（Top 策功/事功，S11 高光个体同源）、透明日志入口（摄政行为/君主决策摘要，复用 B7）。
- **展示原则**：全部为**引用渲染**不落副本（A5）；公示带"天下可查"的先秦仪式语感（"榜于朝门，众目共鉴"）。
- **朝堂烛火**（视觉锚点④）：L3 层级的场景氛围（V1 配合朝堂对话），MVP 以静态构图呈现。

### 3.6 C6 朝堂入口路由

- 斡旋入口（试玩版"大夫之礼"）、L3 朝堂对话（V1，配额归 S1 §4.6）、任务潮接诏入口等统一在朝堂路由，档位校验由本模块执行快照（旬初朝会时点，对齐 REV-003 快照语义）。
- 斡旋的**判定与效果归 S6 外交系统**（正式版 §4.3 判定）——试玩版临时的 `Math.random()<0.7` 内联判定为 MVP 临时规格，正式版迁移。【勘误】试玩版斡旋"每旬 1 次、必选关系最差国"的限频与目标规则并入 S6 动作规格（次数限额语义一致，不冲突）。

## 4. 数据规格

### 4.1 廷议议题 schema

```json
{
  "topic_id": "tp_qi_x14_01",
  "xun": 14, "season": "s1", "nation": "qi",
  "origin": "REGENT_INITIATED",      // REGENT_INITIATED / AI_GENERATED / CRITICAL_AGENDA
  "title": "是否发粟赈济流民",
  "ref_proposal_id": "prop_qi_x14_003",   // 复用 S2 提案结构（dims_target 必填）
  "agenda_slot": 1,                   // 议程位 1-3
  "ai_stance": -2,                    // S1 M6（开议时生成）
  "ai_reason_quote_id": "q_2231",     // 君心反对理由（M7 双审）
  "status": "OPEN"                    // OPEN / ADJUDICATED(S8 产出) / EXPIRED（旬末未裁）
}
```

- 归档规则：`EXPIRED` 议题连续 2 旬未裁 → 从议程池移除并归档（防僵尸议题）；归档议题仍可被新提案引用（旧议重提计新议题）。

### 4.2 上书聚合统计表（C2 输出，回流 S1 M2）

| 字段 | 类型 | 示例值 | 说明 |
|---|---|---|---|
| `xun` / `nation` | | `"x14" / "qi"` | 聚合窗口=旬×国 |
| `topic_votes` | object | `{"TAX_REFORM": 23, "WAR_HAWK": 9}` | 议题 → 去重票数（同玩家同议题旬内计 1） |
| `unique_memorialists` | int | `31` | 本旬上书人数 |
| `slot_usage` | object | `{"rank0_1slot": 12, "rank1p_2slot": 19}` | 格位使用分布（监控双格解锁感知） |
| `capped_players` | array | `["u_88231"]` | 触发 ≤5% 上限截断的玩家（审计用，不惩罚） |
| `petition_tendency` | object | （= topic_votes，字段名对齐 S1 §4.2） | **唯一输出**，回流 S1 M2 |

- 防刷红线：`capped_players` 的超额票**不计入** `topic_votes`（服务端截断，非展示层过滤）；聚合日志全量落盘供透明审计。

### 4.3 议政案记录 schema

```json
{
  "proposal_id": "prop_qi_x14_003",
  "xun": 14, "nation": "qi",
  "proposer_id": "u_88231",
  "agent_draft": false,               // 客卿代拟标记（S7 署名担责，呈递必为本人）
  "yian_text": "缓刑赏、急农桑，先固根本",   // ≤40 字（MVP）
  "dim": "welfare",                   // 必选维度标签【勘误：试玩版 dim:null 修正】
  "status": "ADJUDICATED",
  "verdict": "ADOPTED_SIGNED",        // ADOPTED_SIGNED（采署入诏）/ REJECTED(附君心理由) / ARCHIVED
  "edict_ref": {"xun": 15, "goal_id": "g1"},
  "regent_pinned": false,             // 摄政置顶裁夺标记
  "attribution_window": {"to": "x17"}
}
```

- 采纳后 `proposal_id` 即 S2 策功归因链的提案 ID（同源不同存：S2 拥有归因字段，本表拥有朝堂展示字段——引用 ID 串联，A5）。

## 5. 玩家交互流程（各官阶在朝堂能做什么）

| 档位 | 朝堂身份 | 可做之事 | 频率/限制 |
|---|---|---|---|
| 布衣 | 观政者 | 观诏令/议政案墙/排行榜/透明日志；**上书 1 格**；接诏入口 | 上书旬内 1 格 |
| 下士~上士 | 上书者 | **双格上书**（两条不同议题倾向）；客卿代拟议政案（呈递仍锁） | 上书旬内 2 格 |
| 下大夫及以上 | 朝臣 | **亲笔议政案**（旬 1 件）；**斡旋入口**（判定归 S6）；推举票资格（三条件）；弹劾联署与廷议投票（V1）；L3 朝堂对话（V1，配额 S1 §4.6） | 各项独立限频 |
| 上大夫及以上 | 重臣 | 上述全量 + 摄政竞选资格 + 席位任职通道（S5 P4） | — |
| 卿（席位在任） | 执事 | 上述全量 + 席位职权在朝堂的展示面（太史录名/司徒平准令入口等，S5 权限面） | 随席位 |
| 摄政/次席 | 共治者 | **廷议议题发起（旬 1 次）**、**议政案置顶裁夺**、透明日志被查阅对象；次席：弹劾发起权 + 代理权限（S9：廷议强推 ×1.5、任务潮仅排序） | 旬制 |
| 全体（乡野层，S11） | 旁听者 | 可旁听廷议公告、布告栏诏令摘要；不上书不投票——"野有遗贤"晋升通道另行（S11 court_path） | — |

**关键体验时刻**：
- **旬初朝会**：诏令张贴+议程开列同刻发生（服务器统一时刻），"列国并朝"仪式感；
- **置顶裁夺**：摄政印鉴落在某条议政案上——全国玩家一眼看到"这旬的政由谁在推"；
- **采纳署名**："采某卿之议"五个字出现在诏书上，是朝堂最强的参与回响（S2 归因链闭环的公开时刻）。

### 6.1 上游依赖（本系统消费）

| 系统 | 接口 | 数据 | 依赖等级 |

| S7 客卿 | 代拟上书/议政案草稿（白名单） | C3 `agent_draft` 通道 | 中依赖 |

### 6.2 下游服务（消费本系统）

| 系统 | 数据 |
|---|---|
| S1 M2 | `petition_tendency`（上书倾向，唯一回流出口） |

- 不向决策流输送自由文本（A2：一切政治输入结构化）。

## 7. MVP 裁剪（对照试玩版）

### 7.1 试玩版已实现 → 规格化继承（不再重做）

| 试玩版现状 | 正式化处理 |
|---|---|
| 上书 1-2 格（布衣 1、下士 2，`memoChoices` + localStorage） | 继承格位规则；持久化迁服务端（player_actions, action_type=`memorial`）；旬末"最有效"时点对齐旬快照冻结 |
| 上书影响新旬定策（memoChoices 进新旬生成） | 正式化为 C2 聚合 → `petition_tendency` → S1 M2（去重+≤5% 上限补齐） |
| 亲笔议政案（大夫档+，≤40 字，诏书裁夺） | 继承门槛与 40 字 MVP 上限；【勘误】`dim:null` → 维度标签必选；`action_type` 拆为 `proposal` |
| 客卿代拟上书/议政案（代拟可、大夫亲呈） | 继承并挂 `agent_draft` 审计标记（S7 署名担责） |
| 摄政亲笔置顶裁夺（`【摄政亲笔·置顶裁夺】`） | 继承为 C3 `regent_pinned`——摄政廷议议题发起权的 MVP 表达 |
| 斡旋入口（大夫之礼、旬 1 次） | 入口继承；【勘误】内联随机判定迁 S6 正式判定 |

### 7.2 MVP 砍掉项

| 砍掉项 | 理由 | 恢复时机 |
|---|---|---|
| **廷议集会演出**（烛火大殿场景演出、廷议动画） | 纯演出成本；MVP 玩家-君主互动全走结构化选项（GDD-0 §4.4） | V1 随朝堂对话 |
| **廷议投票环节**（议题投票） | S8 MVP 定稿：威望不足直接否，无投票流程 | V1 |
| **弹劾廷议全流程**（联署/开票） | S8 MVP 简化为威望耗尽自动下台；次席不设 | V1 |
| **席位补选推举**（选举事务的席位侧） | S5 MVP：空缺由 AI 直接任命 | V1；推举票 MVP 仅齐国摄政试点一用 |
| **L3 朝堂对话**（自由对话场合 1） | S1 §4.6：三场合自由对话 MVP-0 整体推迟 | V1 |
| **摄政议题发起权全量**（C1 的 REGENT_INITIATED 日程） | MVP 由"置顶裁夺"承载议题发起语义（齐国试点） | V1 并轨 |

### 7.3 MVP 保留的朝堂骨架

上书聚合回流（C2 完整，含去重与 5% 上限——防刷红线不因 MVP 放松）+ 议政案事务（C3 最小版）+ 公示页（C5 静态版）+ 入口路由（C6）= 支柱三 MVP 验证所需的全部政治参与面。

## 8. 验证指标

### 8.1 核心指标

| 指标 | 定义 | 目标值 | 采集 |
|---|---|---|---|
| **上书参与率** | 旬内上书人数 / 旬活跃人数 | ≥ 25%（布衣 1 格的低门槛设计下） | 聚合日志 |
| **上书-反馈闭环感知**（G1，承接 S1） | "感到被君主听见"问卷（5 分制） | ≥ 3.8 | 月度问卷 |
| **双格解锁感知** | 下士玩家中知道并使用双格的比例 | ≥ 60% | 格位使用分布（slot_usage） |
| **议政案呈递率** | 大夫档玩家旬均议政案呈递人数占比 | 15%-35% 带宽（过低=门槛虚设；过高=话术通胀，复核 40 字上限是否够约束） | C3 日志 |
| **议政案采纳率** | ADOPTED_SIGNED / SUBMITTED | 10%-30%（与 S2 议政案采纳带宽一致，防上书无用感/AI 无主见） | 归因链联动 |
| **朝堂公示渗透**（G2） | 朝堂页周打开率（全玩家） | ≥ 30% | 埋点 |
| **置顶裁夺感知** | 能说出"本旬摄政在推什么"的玩家问卷比例 | ≥ 40%（齐国试点） | 旬度问卷 |
| **廷议参与率**（V1，承接 S8） | 有票权者投票率 | ≥ 60% | C4 日志 |

### 8.2 护栏指标

| 指标 | 阈值 | 说明 |
|---|---|---|
| 刷票拦截率 | 超 5% 上限票 100% 服务端截断（展示层漏放=事故） | G3 红线 |
| 自由文本入流 | 政治输入中自由文本直达决策流条数 = 0 | A2 一票否决 |
| 议程纪律 | 每旬议程 ≤3 项执行率 100%；EXPIRED 僵尸议题积压 = 0 | G5 |
| 跨系统数据一致性 | 朝堂展示字段与源系统不一致数 = 0（抽查） | A5 |
| 档位校验绕过 | 低档位政治动作通过数 = 0（服务端快照校验） | G4 |
