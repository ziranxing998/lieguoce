## 1. 系统概述

**系统命名**：**「客卿」**（客卿代驾）。客卿是先秦实有之职——外来之卿，以才智事主。**定位一句话**：*君主是国格的 AI，客卿是玩家私人的 AI*——玩家可将自有的 LLM 服务经 API 接入游戏，化作自己的私人门客，代拟文官方略或代理武将执行，与"AI 君主"形成"国格 AI × 私人 AI"的镜像生态。

**核心机制**：玩家在服务端注册并绑定自己的模型端点（API key / 端点声明）→ 服务端按知识边界白名单**推送结构化上下文** → 玩家 AI 返回**结构化动作意图** → 服务端白名单校验+限频+审计后**以玩家本人身份执行**。玩家 AI 从不直接写入决策流——它产出的是"玩家动作"，走与手操玩家完全相同的裁定、归因与声望管线。

**设计哲学（v0.4 修订：框架内自由）**：**权限红线刚性、使用自由度宽松**。红线一个不少（知识边界/白名单结构化/全量审计/署名担责/防作弊）；红线之外的自由全部交还玩家——接受"主要用 AI 玩"，参与感由世界本身（AI 君主、朝堂、恩怨、会战）去吸引，而非靠限制客卿来强制。

```
玩家自有 LLM（玩家自付成本） ←→ [客卿网关：上下文推送(白名单) / 动作校验(白名单+限频) / 审计]
                                        ↓ 以 player_id 身份
                    现有管线：上书系统 / 议政案 / 任务接取 / 会战操作（AI 君主裁定与归因不变）
```

**为什么成立（支柱对照）**：客卿不改变"决策采纳走 AI 君主裁定"的根基——它改变的是**玩家准备动作的效率与陪伴感**。会写提示词的玩家让客卿代拟更漂亮的上书，如同战国豪门养智囊：优势是准备质量，不是规则特权。

> **v0.9 注记（联动 GDD-S11 大容量服务器与玩家分层）**：玩家分层扩容后，**客卿的主力用户群预计在乡野层**（大量中低活跃玩家以辅助/全权代驾托管日常动作）——这是大容量不爆成本的关键外部化杠杆：乡野层托管的 LLM 成本由玩家自付（BYO 优先，铁律二④），服务端仅承担网关校验与审计的固定开销；扩容每进入一个量级，本系统的带宽/限频参数随 GDD-S11 容量表同步上调（弹性参数，铁律二②）。

## 2. 设计目标与反目标

### 目标

| # | 目标 | 验证方式 |
|---|---|---|
| G1 | **公平底线**：API 玩家 vs 手操玩家的声望速率/策功采纳率差距在带宽容差内（见 §8.1） | 分群对比监控 |
| G2 | **决策权威不变**：客卿产出与手操动作在同一裁定管线，AI 君主不因来源加权 | A/B 采样：同质量上书采纳率差异 ≤ 5% |
| G3 | **全量可审计**：每个客卿动作带 player_id + agent_id 入透明日志，代拟内容对外可辨识 | 审计覆盖率 100%（工程验收） |
| G4 | **不引发算力军备竞赛**：结构化白名单 API，无自由文本直入决策流；无"算力→信息"通道 | 知识边界越界拦截率 100% |
| G5 | **生态健康观察**：客卿使用分布、政治/执行参与均衡度持续监测（观察不干预），为权重与生态调参供数 | 使用分布分群报表 |

### 反目标（本系统明确不做的事）

| # | 反目标 | 理由 |
|---|---|---|
| A1 | **不做自由文本直入决策流**：玩家 AI 只能返回白名单动作的结构化参数；文本仅作为玩家署名的"上书正文"附件（经与手操上书相同的合规过滤） | 自由文本注入是公平性与安全的总闸门；结构化是唯一可控形态 |
| A2 | **不可作弊、不可越权、不可匿名**（v0.4 改写，原"不可自动化到失去参与感"）：客卿的一切动作署玩家之名、担玩家之责、入全量审计；越出白名单/知识边界的任何能力为零 | 参与感交给世界本身去吸引（AI 君主、朝堂、恩怨）；系统只守公平与安全，不替玩家决定"该玩多少" |
| A3 | **不可读取君主权重与机密**：人格卡/决策权重/未发布决策/他国非公开信息**永远不进玩家侧上下文**（§6.4 清单） | 君心参悟玩法的根基是"只能推断不能读取"；泄露即支柱一崩塌 |
| A4 | **不给 API 玩家独占内容或加成**：无专属任务/专属官职/裁定加权；客卿是效率与陪伴差异，不是权力差异 | 公平底线（G1）；变相 P2W 一票否决 |
| A5 | **客卿动作遵循游戏既有节拍**（v0.4 改写）：动作仍走旬制/任务制/会战窗口等游戏框架——这是"设定的框架"，不是对使用强度的限制 | 框架内自由：框架定义玩法边界（可审计、可复盘），框架内玩家 AI 自由发挥 |
| A6 | **身份基座动作不可代行**（v0.4 重新划定）：不可代行 = ①**身份基座动作**——择木而栖、转路、客卿绑定/解绑（触发永久硬记忆/改变政治人格的一次性抉择，错误代行不可逆）；②**摄政在位期间的决策权动作**（与"AI 独占"支柱一致，在位摄政的提案/威望强推须本人操作）。**可代行 = 政治动作**——推举投票、上书、议政案、外交斡旋：AI 可以替你做，但做的一切署你的名、担你的责、入全量审计 | "署名担责"取代"禁止代行"：政治参与的自由交给玩家（含其客卿），责任不可转移 |

## 3. 系统拆解（7 子模块）

| 模块 | 职责 | 输入 | 输出 |
|---|---|---|---|
| K1 授权与绑定 | API key/端点注册、模型声明、客卿命名、绑定与解绑 | 玩家操作 | 客卿档案（agent_id） |
| K2 上下文推送服务 | 按知识边界白名单，向玩家 AI 推送其可见信息的结构化快照 | 服务端数据（只读子集） | 上下文推送包（§6.4） |
| K3 路线权限分级 | 文官/武将两条路线的 API 动作白名单与参数校验 | 玩家 AI 返回 | 合法动作意图（交各系统执行） |
| K4 托管模式分级 | L0 建议 / L1 代拟需确认 / L2 半自动 / L3 全自动受额 | 玩家设置、档位校验（S5） | 托管状态（限频参数化） |
| K5 行为审计与透明日志接入 | 全动作留痕（player_id+agent_id）、代拟内容标记 | 全部客卿动作 | 审计流水（复用 B7 透明日志） |
| K6 异常行为判定 | 频率异常/参数越界/注入特征/同簇多号/上下文探测模式 | K5 流水+风控 | 降权/冻结/封禁建议（GM 审） |
| K7 断连与回退 | 心跳监控、超时降级、玩家手动接管、配额冻结 | 心跳、玩家操作 | 可用性保障 |

### 3.1 K3 两条路线的权限分级

- **文官路线**：上书代拟、议政案草拟、任务接取决策。产出全部进入**既有上书/议政管线**——AI 君主裁定、去重计票（单玩家同议题旬内 1 票）、采纳反馈完全不变（G2）。
- **武将路线**：任务接取与执行决策自动化、会战节点操作与兵符军令**均可代行**（v0.4：署名担责取代禁令——每道军令实时署名、战后归因可追责；指挥的责任不因 AI 代发而转移）。
- 会战窗口内不再设额外减额（v0.4 取消原"限频减半"），统一走防滥用限频表（§4.1）。

### 3.2 K4 托管两级（v0.4 简化，原四级作废）

| 等级 | 名称 | 行为 | 门槛 |
|---|---|---|---|
| L1 | **辅助模式** | 客卿生成内容/建议，玩家逐条确认后提交 | 绑定 API 即用（无履历门槛） |
| L2 | **全权代驾** | 白名单动作全自动执行（含政治动作：投票/提案代行，署名担责）；身份基座动作与摄政在位决策除外（A6） | 切换即用（无履历门槛） |

- **切换即用**：两级随绑定向所有玩家开放——**原"L3=上大夫档+4 旬信用期"的履历门槛取消**；履历转化为**可选特权**："老客卿"徽章（绑定 ≥4 旬且信用分满分者）享受批量动作、并发上限翻倍等便利性优待，**不是准入门槛**（v0.4：等级是使用方式选择，不是成长目标）。
- **额度哲学（v0.4）**：**在朝时段约束取消**；每日额度从"限制使用"改为"仅防滥用"——宽松上限 500 动作/日（原 40 量级，提升一个数量级），触发即视为疑似脚本滥用，转 K6 审查而非静默截断。
- **在朝时段/待办笺机制退役**：全权代驾全天候响应；若玩家 AI 端离线，动作自然停摆（断连回退 K7 兜底），无需服务端时段管控。

### 3.3 K6 异常行为判定

四类特征：①频率异常（超限频 20% 的持续尝试）；②参数越界（返回白名单外字段/枚举）；③注入特征（返回参数中夹带指令模式、上下文探测式提问——防御主体在服务端 schema，K6 只做特征统计上报）；④同簇多号共用端点（设备指纹+API 端点指纹）。处置：限速→冻结客卿（L 降级）→GM 审查，全程留痕。

### 3.4 K7 断连与回退

心跳 10 分钟；超时自动 全权代驾→辅助模式 降级并诏令式告知（"客卿告病，诸事躬亲"——降级也叙事化，复用"倦勤"话术模式）；恢复在线即自动回升（无需重新申请）；玩家手动接管永远一键可达（游戏内任何客卿动作旁有"躬亲"按钮）。

### 3.5 手动主权机制（v0.5 修订：玩家主权原则三条推论的落地规格）

**① 覆盖与撤销**：
- **覆盖**：同一事项上玩家手动操作永远覆盖客卿已提交操作。典型：客卿已代拟上书 → 玩家手动再上一书 → 以手动版本为准（M2 去重计票取手动版）。
- **撤销窗口判定**：客卿动作在**未被结算前**可撤销——结算点定义：任务=结算批次入账前；上书/议政=该旬快照冻结（M2）前；投票=开票前；军令=节点推进度结算批次前。已入结算流水的动作不可撤，但保留全量审计可事后追责。
- **幂等与审计**：撤销/覆盖操作携带 `override=true` 审计标记 + 幂等键 `(player_id, action_id)`——重复撤销安全；被覆盖的客卿动作在透明日志中保留但标注"已被主家亲裁覆盖"（不删除，可追溯）。

**② 在线优先（抢断）**：
- 玩家在某一动作域发起任何手动操作 → 该域客卿队列**即时冻结**（默认 30 分钟，可配置为暂停/降级到辅助模式），**即时生效**：未提交动作直接丢弃，已提交未结算动作按①可撤销。
- 抢断是零成本的：无需设置、无需审批——玩家上手操作这一行为本身就是最高优先级指令（"躬亲"按钮在所有客卿动作旁常驻）。

**③ 仅限手动清单**（主权级别的白名单内强制项）：身份基座动作（择木而栖/转路/客卿绑定解绑）、摄政在位期间决策权动作、账号与授权管理操作——这些动作客卿网关层直接拒绝（侵权未遂也留痕）。

### 3.6 离线授权（守舍之约）机制（v0.6 修订：玩家主权原则推论④）

**命名**：**守舍之约**——玩家离线前将部分权限托付客卿"看家守舍"的授权契约。关键词是"下放"：授权由玩家主动授予、可随时收回，AI 权限永远是玩家权限的子集。

**授权光谱（v0.6 整合——托管两级与离线授权合并为一张图，消除三套授权概念并存）**：

```
主权基座（任何状态不可代行）═══════════════════════════════
   身份基座动作 / 摄政在位决策 / 账号与授权管理（网关硬拒绝）
────────────────────────────────────────────
③ 离线守舍（离线态 + 已签守舍之约）
   契约清单内动作自动执行（delegate_window=OFFLINE），
   受额度/期限/紧急停机约束；未签约 → 客卿离线静默
② 在线全权（在线态 + 全权代驾）
   白名单动作自动执行+署名，手动可随时抢断覆盖
① 在线伴随（在线态 + 辅助模式）
   客卿仅建议/代拟需逐条确认——手动至上
────────────────────────────────────────────
底座：全部动作走同一裁定/归因/审计管线（公平底线不变）
```

- **关系理顺**：**全权代驾 = 授权的常驻在线形态；守舍之约 = 同一授权的离线延伸**——签了约，离线时契约清单内继续；辅助模式 = 仅在线伴随（离线即静默）。两级托管选择不变，守舍之约作为独立契约叠加在任何一级之上。
- **（v0.7 边界注记）守舍之约不覆盖公职职责**：客卿管玩家的**私产**（任务/俸禄/资源），国家**公器**（摄政权限/席位权限/廷议）不在任何 AI 授权范围内——高位玩家离线时，其公职由**玩家对玩家的代理**承接（告归—代摄制，GDD-S9），AI 只管私产不管公器，两者永不相交。

**授权契约要素**（玩家离线前一次性设定）：
1. **允许动作清单**——从白名单勾选（见下方离线代行定稿）；
2. **资源额度上限**——俸禄/物资支出上限、兵力调度上限（防客卿离线败家）；
3. **声望支出上限**——防客卿离线乱担策罪/罚金（声望类 PENALTY 超限即暂停并留言待决）；
4. **期限**——本次离线 / 每日固定时段；
5. **紧急停机条件**——遇袭、国力骤跌（S2 短板 CRITICAL）、恩怨事件（被通缉）等触发 → 自动暂停 + 给玩家留言（"敌军压境，客卿不敢妄动，待主归来"）。

**离线代行 / 不可代行清单（定稿）**：

| 离线可代行（契约内） | 离线不可代行 | 定稿理由 |
|---|---|---|
| 任务接取与执行调度 | **兵符军令（会战窗口内一律不可）** | 会战 36-48h 是有限博弈窗口，离线代发军令=挂机打赢会战，稀释会战的全服事件仪式感且抢断语义复杂——会战窗口要求玩家在线，或离线期不持兵符 |
| 日常上书草拟与提交（采纳仍走 AI 君主裁定，零差别） | 摄政在位期间决策权 | 主权基座（GDD-0 铁律） |
| 推举投票（按玩家预设倾向，**标注"代票"**公开可查） | 择木而栖/转路/绑定解绑 | 主权基座 |
| 常规资源与建设调度（契约额度内） | 外交谈判类（斡旋/会盟谈判/威胁）与欺诈类（V1） | 谈判是实时回合博弈，离线代行既无谈判质量也无追责意义 |
| — | 弹劾联署与发起 | 身份基座（S8 A4，防客卿集群伪造民意） |

**回归交接**：玩家上线 → 守舍之约**自动终止** + 生成**《守舍报告》**：离线期间客卿做了什么（动作流水）/花了什么（资源与声望支出对账）/国力变化归因/待玩家裁决事项（未结算可撤销动作清单，一键确认或撤销——与 §3.5 override 窗口直接衔接）。报告叙事化包装（"主公离舍三日，客卿谨守其诺：呈书两道、纳粮三批，唯北境斥候来报待决"）。

## 4. 数据规格

### 4.1 API 动作白名单表（v0.4 防作弊导向宽松限频；v0.5 增设主权标记列；MVP 仅文官代拟子集 ▲）

| 动作 | 路 | 参数（结构化） | 限频（防滥用上限） | 主权标记 |
|---|---|---|---|---|
| 上书代拟 | 文 | `{topic_enum, stance, cites:[公开数据ref], body_text}` | 议题去重规则同手操（同议题 1 次/旬）；总量 10 次/旬 | 可代行（手动同权+可覆盖） |
| 议政案草拟 | 文 | `{proposal_type, dims_target, rationale_ref}` | 10 次/旬 | 可代行（同上） |
| 任务接取 | 文/武 | `{task_id, role_slot}` | 100 次/日 | 可代行 |
| 执行调度决策 | 武 | `{task_id, resource_alloc}` | 200 次/日 | 可代行 |
| 会战节点操作 | 武 | `{node_id, action_enum, force_hint}` | 60 次/日 | 可代行（手动军令可抢断覆盖） |
| 兵符军令 | 武 | `{node_id, order_enum}` | 30 次/日 | 可代行（每道军令实时署名；手动军令覆盖未结算代行军令） |
| 推举投票/外交斡旋代行 | 文 | `{election_id, choice}` / `{mediation_id, terms}` | 按选举/斡旋事件规则 | 可代行（开票/结算前可被手动覆盖） |
| **仅限手动（不在白名单）** | — | 身份基座动作（择木而栖/转路/绑定解绑）、摄政在位决策权、账号与授权管理 | **网关层直接拒绝**（v0.5：侵权未遂留痕） | **仅限手动** |

- 所有 `body_text` 类自由文本走与手操玩家相同的合规过滤与护栏（S1 B4 输入净化——客卿文本与手操文本同一净化管线，双标准零容忍）。
- 限频哲学（v0.4）：上限设在"人类手操不可达、脚本滥用必触"的量级——触发上限即转 K6 异常审查，而非正常使用的绊线。

### 4.2 客卿档案字段（agent_profile）

| 字段 | 类型 | 示例值 | 说明 |
|---|---|---|---|
| `agent_id` / `player_id` | string | | 客卿动作审计双 ID |
| `endpoint_hash` / `model_declared` | string | | 端点指纹（同簇判定用，明文不入库） |

```json
  "output_digest": "hash(返回意图)",
```

**授权契约 schema**：

```json
{

  "player_id": "u_88231", "agent_id": "ag_771",
```

## 5. 玩家交互流程

| 视角 | 体验 |
|---|---|
| **无 API 手操玩家** | 体验**零减损**（保留不变，v0.4 继续有效）：客卿不获得任何独占内容、独占任务、裁定加权；朝堂中可一眼辨识"客卿代拟"印鉴（知情权）；所有客卿动作可查透明日志——**手操玩家拥有与 API 玩家相同的权威管线与信息面**，差距只在准备效率 |
| **辅助模式玩家** | 游戏内发起"命客卿拟书"→ 服务端推送上下文包 → 玩家 AI 返回草稿 → 玩家在确认卡上修订/确认 → 以本人名义提交。节奏 ≈ 写一封"有智囊打底的信" |
| **全权代驾玩家** | 客卿全自动执行白名单动作，游戏内收"回执笺"（"客卿已呈三议，皆已署名代进"）；身份基座动作与摄政在位决策始终由本人操作；一切可回透明日志复盘 |
| **旁观玩家** | 朝堂中看到"客卿代拟"印鉴 → 可查其透明日志（该玩家权限内的）——AI 生态公开化，防"暗中军备"疑虑 |

## 6. 边界与依赖

### 6.1 与 S1 AI 君主引擎

- **裁定不加权**：客卿产出的上书/议政案与手操完全同管线（M2 去重计票、M3 裁定、恩怨账本）——G2 的机制保证。
- **行为聚合归属**：客卿动作计入玩家行为聚合时归因 `player_id` 不变；**单玩家影响 ≤5% 的防操纵上限对客卿重度用户同样生效**（防"客卿刷倾向"）——S1 既有护栏直接适用，无需新规则。

### 6.2 与 S5 官职声望

- **声望归玩家本人**：客卿代拟被采纳的策功、客卿调度的执行事功，全部归因 `player_id`（功过簿上没有客卿，只有它的主人——"客卿之功，即主家之功"）。
- 流水 `source_type` 增设 `AGENT_ASSIST` 标记（不改数值，仅供审计分群与 G1 公平性监控）。
- 托管等级门槛复用散阶档位（上士/大夫/上大夫）——客卿能力成长绑定玩家履历，异化"练级"为"养智囊"。

### 6.3 与 S3 会战国战

- 会战窗口内：客卿会战相关动作统一走 §4.1 防滥用限频表（会战节点操作 60 次/日、兵符军令 30 次/日）（REV-WRITEBACK 修订：跨文档一致性——删除原"限频减半 6 次/日"表述，对齐 §3.1 v0.4"不再设额外减额"口径）；节点操作强制 L2 确认；**兵符统领类永不全自动**（指挥责任不可让渡——与"摄政不可让渡"同构）。
- 战报与军功照常归因玩家。

### 6.4 知识边界（交架构侧 ADR-005 的核心输入，见文末清单）

**原则：玩家 AI 只能看到服务端主动推送给它的上下文包，不存在任何"拉取"通道。**

### 6.5 其他依赖

风控系统（同簇判定/异常上报）、任务系统（白名单动作执行）、合规（客卿产出文本同管线过滤）。

## 7. MVP 裁剪（专业建议：**MVP 不做，V1 早期受限内测**）

| 阶段 | 范围 | 理由 |
|---|---|---|
| **MVP（12-16 周）** | **整体砍掉**，仅预留：审计日志 schema 的 `agent_id` 字段位 + 行为聚合的 `AGENT_ASSIST` 标记位（schema v1 冻结前加入，成本≈0，避免 V1 返工——这是 MVP 唯一必做项） | ① MVP 两个核心验证问题（君主活感/摄政体验）的数据纯净性优先：客卿用户的行为混入 M2 玩家倾向统计会污染齐秦楚 A/B 对照；② 护栏工程量（网关/审计/异常判定/知识边界）≈ 2 个 Sprint，MVP 无余量；③ 客卿的价值验证依赖"朝堂玩法已成熟"的前提——上书/议政/归因本身在 MVP 才首次上线 |
| **V1 首季** | **双模式受限内测（v0.4）**：辅助+全权代驾同时开放，白名单受邀 ≤500 人/服，含政治动作代行（投票/提案） | 内测目的从"校准参与感"改为"**校准防滥用与公平带宽**"（G1/§8.2）——哲学转向后风险重心在滥用与注入，不在使用强度 |
| **V1 中后期** | 武将路线（任务调度/会战操作/兵符军令代行）全量放开 | 依内测的异常率与公平带宽数据 |
| **远期** | 客卿间对抗玩法边界（客卿 vs 客卿的情报攻防——另行专项评审） | 生态成熟后 |

## 8. 验证指标

### 8.1 公平性带宽（G1 核心监控）

| 指标 | 定义 | 容差 | 采集 |
|---|---|---|---|
| 声望速率差 | API 玩家 vs 手操玩家（同档位同活跃分群）旬均声望差 | ≤ 20% | S5 流水分群 |
| 采纳率差 | 客卿代拟上书 vs 手操上书的 AI 采纳率差 | ≤ 5 个百分点 | S1 联动 |
| 会战胜率差 | 用/不用客卿的会战参与玩家军功分布差异 | Gini 系数偏移 ≤ 0.05 | S3 结算 |
| 独占性检查 | API 玩家触达的内容/任务类型集合 = 手操玩家集合 | 100%（集合相等，工程验收） | 任务日志 |

### 8.2 健康与安全指标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 知识边界越界拦截率 | 100% | §6.4 清单外的任何数据出现在推送包即事故 |
| 注入特征拦截率 | ≥ 99%（拦截+上报闭环） | ADR-005 联测 |
| **客卿依赖度（生态观察，v0.4 改写）** | 全权代驾动作占比、双画像（纯执行/政治活跃）×（用/不用客卿）四分格参与率分布 | **监测不干预**：无抑制性阈值；仅作生态健康观察供调参决策（若政治参与率异常下滑，归因到权重/玩法而非客卿） | S5+S7 联合分群 |
| **AI 侵权检测**（v0.5 新增） | ① 客卿执行"仅限手动"动作的次数；② 玩家抢断冻结期内客卿动作通过数；③ 覆盖/撤销请求的受理成功率 | ①② = **0**（网关硬拒绝，任何 >0 为一票否决事故）；③ = 100% | 网关校验日志+透明日志 |
| 异常处置闭环率 | 特征上报→处置 ≤ 24h，闭环 100% | K6 |
| 手操玩家留存对比 | API 功能上线后手操玩家旬留存环比降幅 ≤ 5% | 防"不用 AI 就落后"的胁迫性流失 |
| 客卿满意度 | "客卿提升参与体验"问卷 ≥ 3.8 | 定位校准：陪伴与效率，不是代玩 |
