## 三、Sprint 概览（5 轮 × 2 周，每轮 20-30 工时）

### Sprint 1（第 1-2 周）· 地基与冻结
Story（总量 ≈25h）：
1. Go 单体骨架 + 极简 CI（lint/test/build）+ Docker 部署单 VPS【α】
2. **Schema v1 冻结落地**：信封/枚举/队列表/审计表建库（按 schema-freeze-preview.md）【α】【Spike ③ 最小版：冻结签收 + Outbox 同事务 + 队列表消费】
3. **大服-ready schema 位（S11 前置 Story）**：玩家分层字段（tier）、行为聚合表（behavior_aggregates，分组可配置）、分片键 nation_id 确认——**只建结构不做扩容工程**【α】
4. 旬号时钟服务（旬表 + ticker）【α】
5. 账号注册/登录/择国最小（用户名密码，无 OAuth）【δ】
6. **Spike ① 最小版**：单国旬决策链（mock 快照 → 直连 SDK → JSON Schema 校验 → 模板降级）——原 8-10 人日按 solo 砍至 ~3 人日【α】
- **里程碑**：服务器上线，命令行跑出第一份 JSON 国策诏；schema v1 宣布冻结候选。

### Sprint 2（第 3-4 周）· 君主活起来（schema 冻结闸门）
Story（总量 ≈28h）：
1. 人格卡（秦/齐完整、楚原型）+ prompt 组装（缓存+硬记忆注入位）【α】【Spike ② 缩减版：10 条回归输入】
2. 决策快照（三层输入 + **分层统计聚合位**：聚合表 ≤2K token 硬上限）【α】
3. 旬决策 3 国批处理（同步循环，非 Batch API）+ 复盘语录连责 + **降级模板诏令**【α】【Spike ① 收口：3 国全链 + 降级演练】
4. **Schema v1 正式冻结**（Sprint 2 末闸门，按预览稿签收）【α】
5. 任务潮规则引擎最小版（短板加权 → 模板抽取，40% 占比上限）【β】
- **里程碑**：**开发者自己玩到第一旬**——每旬自动收到 3 份风格可辨的国策诏，LLM 挂掉也有模板诏令兜底；成本有 ¥100/日封顶位。

### Sprint 3（第 5-6 周）· 玩法闭环
Story（总量 ≈28h）：
1. 任务实例/接取/完成/结算（发布即声明收益）+ 递减 r=0.7【β】
2. 归因最小版：delta 双账同源（策功/事功流水，trace 全链）【β】
3. 国力三维 + 自然衰减 + 短板检测（40/25）【β】
4. 上书最小版（建议卡 + 旬内去重计数进快照）【β】
5. 语录生成（先秦语感检查 + 机器审，运营抽检=开发者本人）【β】
6. 最小 Web UI（任务列表/上书/诏令阅读——服务端渲染即可，引擎选型推迟到 V1）【δ】
- **里程碑**：**以玩家身份完成"接诏→做任务→看国力动→被旬诏复盘点名"完整闭环**；上书倾向真实影响下旬快照。

### Sprint 4（第 7-8 周）· 文武与一场会战
Story（总量 ≈28h）：
1. 散阶/席位最小版（数据驱动配置；司徒/司马 2 席；席位权重进快照）【γ】
2. 会战状态机 + 剧本化宣战（汉水摩擦→秦自主宣战檄文，走旬决策通道）【γ】
3. 集结期战备值（粮秣/军械/士气）+ 战时任务模板（后粮/军械/动员 3 类）【γ】
4. 3 节点线性推进 + 推进度结算（任务贡献为主）+ 战果申报归因【γ】
5. 战报诏令 + 军功双账 + 灭国占位提示【γ】
- **里程碑**：**打完一场完整剧本会战（秦楚·鄢郢）**：宣战檄文→集结→节点攻防→战报+军功；武将执行路验证成立。

### Sprint 5（第 9-10 周）· 运维收口与内测
Story（总量 ≈24h）：
1. 运维生存清单落地：备份+恢复演练、healthchecks、systemd、旬作业降级演练（solo §6）【δ】
2. 成本熔断接入：¥100/日封顶 + D1-D3 降级链 + 余额告警（solo §3.5）【δ】
3. 埋点最小：核心指标（旬准时率/任务响应率/归因面板数据）SQL 脚本【δ】
4. 大服-ready 验证：队列表压测（~100 rps 写入）+ 旬结算分批复核【δ】
5. 文案与先秦语感打磨 + 内测发布准备（30-100 人内测公告/引导）【δ】
- **里程碑**：**可交给 30-100 人内测**：一旬一诏全自动、成本有封顶、故障自动降级、数据有备份——"开发者睡觉时游戏自己运转"。

**Spike 归属**：Spike ①→S1/S2（最小版收口）；Spike ③→S1（冻结签收）+S2（正式冻结闸门）；**Spike ④ 取消→V1 首任务**；Spike ② 缩减版并入 S2。

## 四、设计侧风险与对齐项（v2 新增/结转）

1. **摄政推迟偏离 GDD-0 §九**（原 MVP 含齐国摄政最小版）——需主理人确认：验证问题②顺延至 V1 早期，MVP-0 以验证问题①（君主活感）为唯一锚；
2. S10/S11 落盘后复核：自由对话"卿大夫档以上可申请"的申请流程规格、分层判据、聚合粒度（对齐 solo §9.5）；
3. MVP-0 会战宣战走"旬决策通道产出檄文"（无独立事件决策）——需设计侧确认叙事可接受（AI 君主在旬诏中宣战而非即时檄文）；
4. 最小 Web UI 采用服务端渲染，客户端引擎（ADR-004）选型顺延至 V1——不影响 schema 与后端架构；
5. 结转 v1 风险：策功分摊规则（S2 §4.5 已标定 ✔ 转入实现）、转路冷却期熟练度规则、封顶线内"旬决策小池 ~¥5/日"建议值待确认。
