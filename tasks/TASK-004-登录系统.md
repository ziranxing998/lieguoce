# TASK-004 登录系统

## 目标
用云服务身份认证替换游客模式（localStorage token），让进度跟着账号走、防多人冒用同一身份。

## 依据文档
- `docs/architecture/architecture-baseline.md` §2.7（玩家 API 与身份边界）
- 所用云平台的身份认证模块文档（WorkBuddy 云服务 Auth：`cloud.auth`，支持邮箱/手机验证码/微信/WorkBuddy 账号）

## 验收标准
1. 首次进入引导注册/登录；老玩家（游客 token）首次登录时可选择"认领旧进度"；
2. `players` 表加 `owner_id` 列 + 行级安全策略（所有者才能读写自己的行），国家/world 表维持公开读；
3. 登出、换设备恢复进度均可用；
4. 未登录状态只能浏览，不能办差。

## 规模
中。注意：数据库行级安全策略必须先于前端改动部署。
