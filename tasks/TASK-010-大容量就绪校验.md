# TASK-010 大容量就绪校验

## 目标
验证"单服 1000-3000 人"的架构承诺：决策输入的分层统计聚合（AI 君主只看聚合摘要不看个体明细）从现在就做进数据结构，避免以后迁移。

## 依据文档
- `docs/design/systems/GDD-S11-大容量服务器与玩家分层.md`（P3 统计聚合、成本亚线性承诺：人数×10 → AI 成本 ≤×4）
- `docs/architecture/solo-dev-architecture.md` §9 容量路线图

## 验收标准
1. 玩家表加 `stratum`（core/rural）分层字段——首版按"是否任官"自动判定，纯配置；
2. AI 君主旬决策 prompt 的玩家行为输入改为聚合摘要（按分层统计），硬上限 ≤2000 字符；
3. 写一个验证脚本：模拟 1000 名玩家的行为数据，证明聚合后 prompt 大小恒定、旬决策成本不随人数增长；
4. 个体数据仅两个例外可进 prompt：Top-5 贤才名录、恩怨记录 ≤50 条。

## 规模
中。依赖 TASK-004（真实身份后分层才有意义）。
